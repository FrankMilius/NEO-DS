NEO Design System · Token-Audit · 08.09.2026

Token-Audit

Bestandsaufnahme aller Tokens des NEO Design Systems: Quelle data/design-tokens.json, Definitionen in scss/scss/00-settings, Wirkung im gebauten CSS. Geprüft wurden Nomenklatur, Vollständigkeit, Verweise und Abweichungen zwischen den drei Ebenen.

Urteil. Die Architektur ist professionell und in Teilen über dem Branchenstandard. Die Umsetzung ist es an drei Stellen nicht: die Quelle widerspricht dem CSS bei den semantischen Farben, 23 Verweise laufen ins Leere, und das Namensvokabular wurde nie festgeschrieben, weshalb 21 Präfixe und drei Größenvokabulare nebeneinander existieren. Das Inventar liegt trotzdem vollständig bei, mit allen Befunden als Flags je Token.

1 · Was das System heute ist

Drei Ebenen, wie in CLAUDE.md beschrieben: Primitive (--fnd-primitive-*, seit August auch die OKLCH-Leitern --fnd-neutral-* und --fnd-accent-*), semantische Rollen (--fnd-color-* in vier Themen), Komponenten-Tokens (--nc-*). Dazu die nicht farbigen Foundations: Spacing 01–13, Radien, Rahmen, Schatten und Erhebung, Motion, Z-Index, Größen, Typografie mit fluider Skala --fs-*, Tracking, Opacity, Breakpoints, Barrierefreiheit. Seit dem 24.08.2026 liegt darüber das monochrome Thema mit eigenen Rollen und einer Brücke, die die Alt-Token auf die Leitern umbiegt.

2 · Fehler

Dinge, die heute falsch wirken oder eine Prüfung brechen. Reihenfolge nach Wirkung.

Fehler 123 Verweise laufen ins Leere, 40 Stellen ohne Fallback

Im gebauten CSS werden Custom Properties gelesen, die nirgends definiert sind. 17 davon im Foundation-Namensraum: --fnd-motion-ease-ease-in-out, --fnd-motion-ease-ease-out, --fnd-motion-ease-linear (die Skala heißt informative/focused/expressive), --fnd-motion-duration-700 (es gibt 600), --fnd-spacing-9 (heißt 09), --fnd-color-background-inverted, --fnd-color-text-on-inverted, --fnd-color-interactive-subtle, --fnd-color-feedback-success-border/-text, --fnd-elevation-flat, --fnd-elevation-navigation, --fnd-typography-body-m/s-font-size, --fnd-typography-fonts-body/-heading, --fnd-typography-paragraph-xs-size. Dazu --nc-input-placeholder-color (Select), --nc-input-radius-md (Textarea), --body-font-size-xs (Footer), --marquise-* (Question), --min-footer-height (Reset). Fundorte: _component-tokens.scss, _docs.scss, Popover, Dropdown, Search, Status, Progress.

Namen korrigieren oder fehlende Tokens anlegen. Einen Linter lint:refs einführen, der das gebaute CSS auf var() ohne Definition und ohne Fallback prüft; das Skript aus diesem Audit kann direkt übernommen werden.

Fehler 2Der Validator schlägt fehl: 100 Fehler, 274 Warnungen

98 Fehler, weil ref in der Komponenten-Registry auf Foundation-Namen zeigt (spacing-08, radius-sm, motion-ease-linear), der Validator aber nur semantische Farb-IDs kennt. Ein Fehler „primitives.neutral is empty“, weil neutral am 24.08.2026 nach system umgezogen ist und der Validator nicht nachgezogen wurde. 26 doppelte Komponenten-IDs (nc-form-error-*, nc-form-hint-*, nc-form-label-*, nc-icon-button-*, nc-input-group-addon-* stehen in zwei Gruppen). Dazu 267 Warnungen, weil Tokens nicht mit dem Namen ihrer Gruppe beginnen.

Validator an den Vertrag anpassen (Foundation-Refs erlauben, system.neutral lesen), Duplikate einer Gruppe zuordnen. Danach tokens:validate wieder als Pflichtschranke in npm test aufnehmen; heute läuft er dort nicht.

Fehler 3design-tokens.json widerspricht dem gebauten CSS bei den semantischen Farben

Die JSON-Vorgaben tragen noch das blaue System: neo-light.text-primary #0f1419, interactive-default #009fe3. Das CSS liefert #000000 und #595c59 (Graphit 700). Die JSON kennt 56 Rollen je Thema, die SCSS-Maps 71, die JSON-Gruppen 79. 16 Rollen gibt es nur im SCSS (background-quinary, border-hairline, border-mid-dark, text-difference, scrollbar-*, selection-*, surface-elevated …), 23 nur in der JSON (die Mono-Rollen). Wer aus der JSON exportiert, etwa Theme-Konfigurator oder Figma, bekommt das alte Blau. $meta.last_updated steht auf 2026-02-19, die Datei wurde zuletzt am 05.09.2026 geändert. Der Golden Master ist vom 11.08.; tokens:diff meldet 1427 neue, 755 entfernte, 2880 geänderte Einträge und ist damit als Drift-Wächter wirkungslos.

Eine Richtung festlegen: entweder werden die SCSS-Farbmaps aus der JSON erzeugt (wie bei Spacing, Radien, Motion) oder die JSON wird wie die Primitives aus dem SCSS geschrieben (primitives-aus-quelle.cjs auf Semantik ausweiten). Danach Golden Master und last_updated mit jedem Commit pflegen.

Fehler 4design-tokens.css ist als Ausgabe für Nicht-SCSS-Nutzer unbrauchbar

537 Namen, davon stimmen 41 mit dem gebauten CSS überein. Der Generator schreibt JSON-Pfade (--fnd-radii-scale-md) statt der Kurznamen (--fnd-radius-md), und er schreibt Notizen und Oberflächentexte als Werte hinaus: --fnd-typography-fluid--notiz: Getrennte Verhaeltnisse …, --fnd--configurator-radius-tokens-sm-label: SM (Default), --fnd-state-derivation-bold-description.

Die Datei aus dem gebauten CSS ableiten (Filter auf :root und --fnd-*) oder ganz streichen. Schlüssel mit führendem Unterstrich (_notiz, _configurator) grundsätzlich vom Flatten ausnehmen.

Fehler 5Rahmenbreiten: Aliasse stehen auf dem Kopf, Kommentar beschreibt die alte Skala

medium → lg = 3px, thick → md = 2px: „medium“ ist dicker als „thick“. Der Kopfkommentar in _border.scss nennt sm 2px, md 4px, lg 6px, xl 8px; die JSON hat seit 12.08.2026 1,5 / 2 / 3 / 4 px. Von sechs Aliassen wird nur hairline benutzt (10 Stellen).

Aliasse auf hairline und default reduzieren, den Rest streichen; Kommentar aus der JSON generieren statt von Hand pflegen.

Fehler 6Zwei Z-Index-Skalen, die sich widersprechen

JSON: base 1, dropdown 2, sticky 3, fixed 9, modal-backdrop 10, modal 11, tooltip 20. Nur im SCSS: header 100, sidebar 200, drawer 300, notification 400, toast 500, skip-link 9999. Damit liegt --fnd-z-modal (11, genutzt in _modal.scss) unter --fnd-z-header (100, genutzt in _header.scss) und --fnd-z-tooltip (20) unter jedem Drawer (300). Zusätzlich 20 rohe z-index-Zahlen in Timeline, Accordion, Card-CTA, Radio-Group, Searchbar.

Eine Skala mit acht benannten Stufen in aufsteigender Ordnung (base, raised, sticky, header, drawer, modal-backdrop, modal, toast, tooltip, skip-link) in der JSON führen und die SCSS-Ergänzungen dorthin ziehen. Rohe Zahlen innerhalb einer Komponente als --_z-* kennzeichnen.

Fehler 7Doppelte Deklarationen mit verschiedenen Werten

--nc-toast-shadow steht zweimal in _component-tokens.scss (Zeile 1436: elevation-floating, Zeile 1893: elevation-raised). --nc-fade-gallery-tab-aria-selected-true-after-border-radius steht in der Hauptdatei auf radius-full und in der aufgenommenen Datei auf radius-null. Vier weitere Namen sind wortgleich doppelt (--nc-toast-padding, --nc-toast-radius, zwei Fade-Gallery-Opacities).

Duplikate auflösen und den Sync-Check um eine Duplikatprüfung innerhalb von :root erweitern.

Fehler 8Fokusring und Touch-Ziel sind mehrfach und verschieden definiert

Fokus-Offset: JSON a11y.focus_ring.offset 3px, SCSS --fnd-focus-offset 2px; die JSON nennt als Farbe text-primary, das Mono-Thema arbeitet mit focus-inner/outer. Touch-Ziel 44 px: --fnd-touch-target-min, --fnd-size-touch-target, --nc-button-touch-target-min, --nc-chip-touch-target-min, --nc-icon-touch-target, dazu icons.touch_target_min und a11y.touch_target_min in der JSON; drei davon als rohe 44px.

Je Größe genau einen Foundation-Token (--fnd-size-touch-target, --fnd-focus-offset), alle anderen als Verweis darauf. Die JSON-Werte auf die SCSS-Werte ziehen.

3 · Lücken

Dinge, die fehlen oder doppelt vorhanden sind, ohne dass etwas sichtbar kaputt wäre.

Lücke 1Drei semantische Farbsysteme laufen nebeneinander

(a) --fnd-color-*: 71 Rollen in 4 Themenklassen, 4 veralteten Klassen und prefers-color-scheme; (b) das Mono-Thema: 41 Rollen ohne Präfix (--surface-*, --text-*, --border-*, --interactive-*, --accent-*, --feedback-*, --focus-*, --elevation-*), im CSS von keiner Komponente gelesen; die Brücke biegt stattdessen die Alt-Token um; (c) die JSON-Gruppen mit 79 IDs. Rollen überlappen: layer-01…03 gegen surface-01…03 gegen background-secondary/tertiary; border-primary/secondary/strong gegen border-subtle/control/emphasis gegen border-hairline/mid-dark; interactive-focus gegen focus-inner/outer; accent-text und text-accent existieren beide in der JSON.

Zielbild benennen: die Mono-Rollen sind das jüngere, besser begründete Vokabular (OKLCH-Leitern, WCAG-Rollen). Sie unter --fnd-color-* führen, die Alt-Rollen als Aliasse mit Ablaufdatum, dann Komponente für Komponente umziehen wie in _mono-bridge.scss angekündigt.

Lücke 2Primitives sind mehrfach kopiert, zwei Lime-Leitern unterscheiden sich

brand.primary, brand.secondary und neutralleitern.graphit sind dieselbe Leiter in drei Kopien; system.neutral (#7a7a7a) ist eine vierte Grauleiter. brand.accent und neutralleitern.lime haben denselben Grundwert #37e93d, weichen aber ab Stufe 600 ab (700: #218c25 gegen #009612). Im CSS heißt das --fnd-primitive-accent-700 ≠ --fnd-accent-700. Die Akzentleiter steht zudem in der Gruppe „neutralleitern“.

Eine Leiter je Farbe. brand.primary/secondary als Verweis auf Graphit modellieren, eine Lime-Leiter behalten (die OKLCH-Leiter aus _neutral-ramps.scss), system.neutral streichen oder als „Grau ohne Stich“ begründen. Gruppe in leitern mit Unterteilung neutral/akzent umbenennen.

Lücke 3278 Primitive im CSS, 252 davon von niemandem gelesen

15 Stützpaletten (neo-blue, neo-darkblue, beige, chartreuse, pink, aqua, cyan, burgundy, coral, mustard, sage, warm-taupe, pearl-white, old-gold, dark-orange) werden mit je 10 Stufen ins CSS geschrieben und nirgends verwendet, ebenso primary/secondary (11 Stufen) und black/white (10 Alpha-Stufen). Genutzt werden nur die Stufe 500 der vier Systempaletten über das Mono-Thema.

Paletten in der JSON behalten, aber nur ins CSS schreiben, was referenziert wird, oder die Stützpaletten als eigenes, optionales Stylesheet ausliefern. Spart rund 250 Deklarationen in jedem :root.

Lücke 4Foundation-Tokens ohne Abnehmer

46 Foundation-Namen werden weder im CSS noch in Docs, Website, Konfigurator oder Drupal-Theme gelesen: alle neun --fnd-motion-delay-*, vier Dauern (100, 250, 350, 600), alle acht semantischen Dauern informative/focused/expressive-*, --fnd-motion-ease-expressive, alle fünf --fnd-bp-*, vier --fnd-state-*, drei --fnd-text-transform-*, --fnd-size-2xl, --fnd-size-touch-target, --fnd-radius-default, --fnd-content-wide-max-width, --fnd-tracking-tighter, --fnd-spacing-gutter-lg, --fnd-spacing-inset-squish. Die rollenbasierten Abstände (section, component, element, inline, stack, inset, gutter) werden von keiner Komponente benutzt, nur in Docs erwähnt.

Je Token entscheiden: benutzen, dokumentieren oder streichen. Die semantischen Motion-Dauern und die Spacing-Rollen sind gut gedacht; sie brauchen einen ersten Abnehmer, sonst bleiben sie Behauptung.

Lücke 5143 Komponenten-Tokens ohne Abnehmer, 82 Komponenten-Tokens ohne Registrierung

Nirgends gelesen: hero 23, nav 22, card 16, accordion 15, story-gallery 12, input 11, search 11, container 10, section 9. Umgekehrt stehen 82 --nc-* im CSS, die in der JSON-Registry fehlen (bento-grid-cell-*, bleed-*, block-*, button-inverted/soft/press/ripple-*). tokens:sync:check meldet nur die Richtung Registry → SCSS als Fehler; die andere Richtung erscheint als Hinweis und 139 Registry-Einträge haben kein SCSS-Gegenstück.

Sync in beide Richtungen als Fehler werten. Unbenutzte Komponenten-Tokens nach einer Schonfrist entfernen; wer sie für Overrides vorhält, dokumentiert das an der Komponente.

Lücke 6Dokumentation deckt die neueren Familien nicht

Keine Docs-Seite erwähnt --fnd-tracking-*, --fnd-neutral-* und --fnd-accent-* (die Leitern), --fnd-underline-*, --fnd-bp-*, das Mono-Thema (neo-mono-light, data-neutral) oder das --mod-*-Override-Muster, das mit 2110 Haken das meistgenutzte Muster im CSS ist. --lh-* kommt in zwei Seiten vor. Die 16 nur im SCSS vorhandenen Farbrollen haben nirgends eine Beschreibung.

Eine Foundation-Seite „Leitern und Mono-Thema“, eine Seite „Override-Haken“ und Beschreibungen für die 16 Rollen in der JSON nachziehen. Die Docs-Token-Prüfung (lint:docs-tokens) um „jede Familie hat eine Seite“ erweitern.

Lücke 7Figma-Pipeline liefert nichts

data/figma-resolved.json enthält leere Objekte (colors {}, typography {}, effects {}). Die Variablen der Figma-Styleguide-Datei und die Tokens im Repo haben keine gemeinsame Quelle; der Tokens-Studio-Export ist seit Februar offen.

Nach der Bereinigung der Quelle (Befund 3) den Export im Tokens-Studio-Format aus design-tokens.json erzeugen und in Figma einlesen. Vorher lohnt es nicht.

Lücke 8Kontrastprüfung hat keinen Referenzstand

npm run kontrast verlangt einen Referenzstand und bricht ohne ab; die Baselines unter data/baseline stammen aus einzelnen Umbauten. Das Mono-Thema dokumentiert selbst, dass feedback-warning (#d4a400) als Schrift auf Weiß nur 2,31:1 erreicht und success/danger/info 3,35:1.

Einen festen Referenzstand aktuell pflegen und die Prüfung in npm test hängen. Für die Rückmeldefarben als Schrift die Stufe 700 der Systempaletten als text-success usw. binden, wie der Kommentar in _mono-theme.scss es vorschlägt.

4 · Nomenklatur und Benennung

Die Regeln in CLAUDE.md nennen zwei Präfixe, BEM für Klassen und Verbote für Rohwerte. Ein Vokabular für Eigenschaften, Stufen, Gruppen und Sprachen gibt es nicht; die Befunde sind die Folge.

Nomenklatur 121 Präfixe statt der zwei aus der Konvention

3427 Custom Properties im CSS: 2653 --nc-, 587 --fnd-, 64 private --_, 41 Mono-Rollen ohne Präfix, 14 --fs-, 13 --mod--Definitionen, 10 --container-, 7 --lh-, 7 --neo-color-* (Relikte, unbenutzt), 4 --fluid-, 4 --sg-, 3 --font-, 3 --square-, 3 --docs-, dazu --grid-gap, --columns, --nav-height, --noop, --time-to-wait. Die Regeln in CLAUDE.md kennen nur --fnd- und --nc-.

Präfix-Vertrag festschreiben: --fnd- Foundation, --nc- Komponente, --mod- Override-Haken (nur lesen, nie deklarieren), --_ privat innerhalb einer Komponente. --fs-, --lh-, --font- nach --fnd-type-* ziehen und die alten Namen als Aliasse mit Ablaufdatum lassen; --neo-color-* und --sg-* streichen.

Nomenklatur 2Drei Vokabulare für Größenstufen

Typografie zählt 2xs … 9xl (--fs-*), dann xxs, xs, s, m, l, xl, 2xl (--fnd-typography-heading-*) und schließlich Rollen display-l, heading-m, body-s (--nc-type-*). Radien, Größen und Buttons nutzen xs/sm/md/lg/xl. „s/m/l“ und „sm/md/lg“ meinen dasselbe und stehen nebeneinander. Die Rollen-Rampe liegt unter --nc-type-*, obwohl sie Foundation ist.

Ein Stufenvokabular (xs … xl, darüber 2xl …), ein Rollenvokabular (display/heading/body/label/caption mit l/m/s). --nc-type-* wird --fnd-type-*; --fnd-typography-{display,heading,paragraph}-* läuft aus.

Nomenklatur 3Eigenschaftsnamen in Komponenten-Tokens sind nicht normiert

Gezählt über 2597 registrierte Tokens: bg 296 gegen background 9; radius 140 gegen border-radius 8; weight 106 gegen font-weight 54; lh 17 gegen line-height 24; ls 11 gegen letter-spacing 13; padding-x 29 gegen padding-inline 13; padding-y 18 gegen padding-block 16; shadow 50 gegen box-shadow 3; border (gemeint: Rahmenfarbe) 235 gegen border-color 19.

Ein Eigenschafts-Wörterbuch mit genau einer Form je Eigenschaft (bg, color, border, border-width, radius, shadow, size, weight, lh, ls, padding-x, padding-y, gap) und ein Lint, der die Nebenformen meldet. Die Mehrheitsform ist jeweils die kurze.

Nomenklatur 4Gruppennamen: Abkürzungen, Nahduplikate und Fremdkörper

Abkürzungen: nc-cs-* (code-snippet, 68), nc-dt-* (data-table, 122), nc-refpage-*, nc-tbl-*, nc-app-*; 267 Tokens beginnen nicht mit dem Namen ihrer Gruppe. Nahduplikate in der Registry: chapternav und chapter-nav; dropdown und dropdown-menu; table, data-table, table-block, tbl-cell, compare-table; hero, hero-tmob, hero-tom; search und searchbar; tabs, tab-nav, solution-tabs; event und events; drawer und mobile-drawer. Foundation-Themen unter --nc-: type, mono, anim, grid, container, section, kicker, group, parallax, nav.

Gruppenname = Dateiname der Komponente, ohne Abkürzung. Nahduplikate zusammenführen oder als Varianten der einen Komponente führen. Die Foundation-Gruppen nach --fnd- verschieben.

Nomenklatur 5Namen, die Selektoren statt Rollen beschreiben

Elf Tokens aus der Drupal-Aufnahme tragen den Selektor im Namen: --nc-fade-gallery-tab-aria-selected-true-after-border-radius, --nc-compare-table-sticky-col-th-first-child-after-background, --nc-table-block-is-scrolled-nc-compare-table-sticky-col-th-first-child-after-opacity, --nc-testimonial-video-facade-hover-after-background. Dazu 33 Komponenten-Tokens mit rohen Hex- oder rgba-Werten und 377 mit rohen Längen im :root; der Grundsatz der Datei lautet „nie direkte Hex-Werte“.

Nach Rolle benennen (--nc-fade-gallery-tab-active-radius, --nc-compare-table-sticky-shadow). Rohe Werte über Foundation binden oder mit // bewusst begründen; lint:tokens auf die Deklarationsdatei ausweiten, heute prüft er nur die Konsumenten.

Nomenklatur 6JSON-Schlüssel: snake_case, Deutsch und Englisch, Sonderfälle

83 Foundation-Schlüssel in snake_case (base_unit, z_index, modal_backdrop, duration_semantic) neben kebab-case-IDs; der Generator wandelt still um. Deutsche und englische Schlüssel gemischt (neutralleitern, praesentation, _notiz neben supporting, foundation); Labels der neuen Gruppen deutsch („Bühne“, „Erhebung“), der alten englisch („Primary Text“). Spacing-Schlüssel als nullgefüllte Strings "01"…"13", wodurch 10–13 in der Datei vor 01 stehen. Radius-Schlüssel "null" für 0 px. Breakpoints als Zahl (xs: 0) und String ("768px") gemischt. Opacity mischt Metaphern: muted 0.6, medium 0.7, high 0.8, prominent 0.85, subtle 0.9; „subtle“ ist der deckendste Wert.

Eine Sprache je Ebene festlegen (Schlüssel und IDs englisch, Beschreibungen deutsch), snake_case in der Quelle abschaffen, null zu none, Breakpoints einheitlich als px-Strings, Opacity als Skala disabled/hover/focus/pressed/dragged plus o-60/o-70/o-80/o-85/o-90 oder mit eindeutigen Rollen.

Nomenklatur 7Veraltete Namen sind die tatsächliche Schnittstelle

--grid-gap (112 Stellen), --columns (98) und --container-max-width (14) sind als „Legacy-Aliase“ markiert, werden aber häufiger gelesen als die Ziele --nc-grid-* und --nc-container-*. Umgekehrt werden --fnd-radius-s/m/l/2xs und fünf Rahmen-Aliasse nie gelesen, bleiben aber im CSS. Vier veraltete Themenklassen (light-base-theme …) stehen noch in 7 Docs-Dateien. Insgesamt existieren drei Generationen von Themen-APIs nebeneinander: Klassen, data-theme, neo-mono-* mit data-neutral.

Was breit genutzt wird, ist kein Alias: --grid-gap und --columns entweder offiziell machen (--fnd-grid-gap, --fnd-grid-columns) oder per Codemod ersetzen. Ungenutzte Aliasse sofort streichen. Themen-API auf eine Form festlegen und die Docs nachziehen.

5 · Was bleiben soll

Stärke 1Was gut ist und bleiben sollte

Die Dreischichtung ist konsequent: 836 von 2653 Komponenten-Tokens lesen --fnd-color-*, 367 Spacing, 124 Radien; kein Komponenten-Token greift auf --fnd-primitive-* zu. Die OKLCH-Leitern mit stufengleichem Kontrast, die Trennung von Bedienung und Akzent, die zwei Rahmenrollen nach WCAG 1.4.11 und der zweischichtige Fokusring sind über dem Branchenstandard begründet. Das --mod--Override-Muster (Spectrum-Stil) ist sauber umgesetzt. Die Werkzeugkette (Validator, Sync, Lint, Golden Master, Baselines) ist vorhanden; sie ist nur nicht überall scharf gestellt.

Das Audit stellt keine Architekturfrage. Es geht um Drift zwischen Quelle, SCSS und CSS und um ein Namensvokabular, das nie festgeschrieben wurde.

Quelle: data/design-tokens.json (738 KB, Vertrag 2.0.0), die 31 Dateien in scss/scss/00-settings, ein frischer Build von main.scss vom 08.09.2026.
