NEO Design System

Composition Rules

Verbindliche Regeln für die Komposition von Komponenten im NEO Design System. Die Regeln leiten sich aus der Atomic-Design-Hierarchie (Objects → Atoms → Molecules → Organisms → Templates) und dem Layout Composition System ab.

Atomic-Design-Hierarchie

Komponenten sind in ITCSS-Schichten organisiert. Die Schichtnummer bestimmt, welche Komponenten ineinander verschachtelt werden dürfen. 

Template  (08-templates)
    ↓
Organism  (07-organisms)     z.B. Header, Footer, Modal, Carousel
    ↓
Molecule  (06-molecules)     z.B. Card, Accordion, Breadcrumb
    ↓
Atom      (05-atoms)         z.B. Button, Icon, Input, Badge
    ↓
Object    (04-objects)        z.B. Container, Grid, Section

Nesting-Regeln

# Regel Beispiel
1 Eine Komponente darf nur Komponenten aus der gleichen oder niedrigeren Schicht enthalten. Organism (07) → Molecule (06) + Atom (05)
2 Ein Organism (07) darf niemals einen anderen Organism enthalten. Modal darf keinen Header enthalten
3 Eine Molecule (06) darf nur Atoms (05) enthalten, keine Organisms (07). Card enthält Button + Badge, nie Carousel
4 Templates (08) orchestrieren Organisms innerhalb von Sections. .t-dashboard ordnet Header, Sidebar, Content an
5 Objects (04) sind Layout-Wrapper — sie enthalten Inhalt, keine anderen Objects. Container enthält Grid, aber Grid enthält keinen Container

Section als Orchestrator

Das kanonische Layout-Pattern: Section → Container → Grid → Inhalt.

HTML 
<section class="section">
  <div class="nc-container">
    <div class="o-grid">
      <!-- Organism- oder Molecule-Inhalt -->
    </div>
  </div>
</section>

Verschachtelungs-Matrix

Erlaubte Verschachtelungen der Layout-Primitive.

Primitiv In sich verschachteln? Grund
.nc-container NIEMALS Doppelte max-width/padding führt zu falschem Layout
.o-grid Erlaubt Innere Grids setzen den Spalten-Kontext zurück
.section NIEMALS Sections sind Top-Level-Blöcke, keine verschachtelbaren Wrapper

Semantische Spacing-Hierarchie

Spacing-Tokens definieren konsistente Abstände für jeden Kontext. Die Hierarchie folgt dem Prinzip: größerer Kontext → größerer Abstand.

Kontext Token Skala-Stufe Wert Verwendung
Zwischen Sections --fnd-spacing-section 12 80px Section padding-block
Zwischen Komponenten --fnd-spacing-component 08 32px Gap zwischen Organisms/Molecules
Zwischen Elementen --fnd-spacing-element 04 16px Gap innerhalb einer Komponente
Grid Gutter --fnd-spacing-gutter 04 16px Grid Gap
Inline Spacing --fnd-spacing-inline 03 12px Horizontal zwischen Geschwistern
Stack Spacing --fnd-spacing-stack 04 16px Vertikal zwischen Geschwistern
Inset Padding --fnd-spacing-inset 04 16px Gleichmäßiges Padding rundum

Grundregeln

# Regel Begründung
1 Komponenten setzen niemals eigenes äußeres Spacing (margin). Der Eltern-Container steuert Abstände über gap oder margin.
2 Verwende gap statt margin für Abstände zwischen Geschwistern in Grid/Flex. gap vermeidet Margin-Collapse und vereinfacht das Spacing-Modell.
3 Section-Padding wird über --nc-section-padding-block gesteuert. Modifier-Klassen: --compact (klein), --spacious (groß).
4 Stufen 06–13 sind fluid (clamp()), Stufen 01–05 sind statisch. Große Abstände skalieren responsiv, kleine bleiben fix.

Spacing-Pattern im Code

CSS 
/* Richtig: Parent steuert Spacing via gap */
.my-layout {
  display: flex;
  flex-direction: column;
  gap: var(--fnd-spacing-component);  /* 32px zwischen Kindern */
}

/* Richtig: Section-Padding über Token */
.section {
  padding-block: var(--nc-section-padding-block);
}
.section--compact {
  --nc-section-padding-block: var(--fnd-spacing-08);
}
.section--spacious {
  --nc-section-padding-block: var(--fnd-spacing-13);
}

/* Falsch: Komponente setzt eigenes Margin */
.nc-card {
  margin-bottom: 32px;  /* NIEMALS! */
}

Layout-Recipe-Pattern (LayoutSpec)

Ein Layout wird aus 4 Primitiven zusammengesetzt. Jedes LayoutSpec referenziert Presets über ref und kann diese per overrides anpassen. Abgeleitete Layouts nutzen extends.

Primitiv Verantwortung Token-Präfix
Container Horizontale Breitenbegrenzung + Zentrierung --nc-container-*
Grid Spalten-System, Gap, Alignment --nc-grid-*
Spacing Vertikaler und horizontaler Rhythmus --fnd-spacing-*
Section Orchestrator — verbindet Container, Grid, Spacing --nc-section-*

Verfügbare Basis-Layouts

Layout Container Grid Gap Section Use Case
Marketing Wide (1440px) Large Spacious Landing Pages
Docs Standard (1200px) Default Default Dokumentation
Dashboard Full (100%) Small Compact Admin Panels
Form Narrow (768px) Default Default Formulare
Content Standard (1200px) Default Default Artikel, Blog

Template-Klassen

Jedes Basis-Layout wird über eine Template-Klasse .t-{layout-name} angewendet. Die Klasse setzt alle zugehörigen Token-Werte auf einmal.

HTML 
<!-- Marketing-Layout: breiter Container, großzügige Sections -->
<div class="t-home-hero">
  <section class="section section--spacious">
    <div class="nc-container">
      <div class="o-grid">...</div>
    </div>
  </section>
</div>

<!-- Dashboard-Layout: volle Breite, kompakte Sections -->
<div class="t-dashboard">
  <section class="section section--compact">
    <div class="nc-container">
      <div class="o-grid">...</div>
    </div>
  </section>
</div>

Ableitung per extends

Neue Layouts können von einem Basis-Layout erben und nur Abweichungen überschreiben.

JSON 
{
  "name": "blog",
  "extends": "content",
  "overrides": {
    "container": { "max-width": "860px" },
    "section": { "padding-block": "var(--fnd-spacing-10)" }
  }
}

Entscheidungsbaum

So wählen Sie das richtige Basis-Layout: 

Ist der Inhalt eine Landing Page?
  → Ja: Marketing (Wide, Spacious)
  → Nein:
    Ist es ein Admin-/Dashboard-Bereich?
      → Ja: Dashboard (Full, Compact)
      → Nein:
        Ist es ein Formular?
          → Ja: Form (Narrow, Default)
          → Nein:
            Ist es Dokumentation?
              → Ja: Docs (Standard, Default)
              → Nein: Content (Standard, Default)

Häufige Fehler & Korrekturen

Diese Anti-Patterns verstoßen gegen die Composition Rules. Jedes Beispiel zeigt den Fehler und die korrekte Lösung.

1. Verschachtelte Container

❌
Falsch: Container in Container
<div class="nc-container">
  <div class="nc-container">  <!-- FALSCH -->
    ...
  </div>
</div>
✓
Richtig: Ein Container pro Section
<section class="section">
  <div class="nc-container">
    <div class="o-grid">...</div>
  </div>
</section>

2. Hardcodiertes Spacing

❌
Falsch: Pixel-Wert direkt im CSS
.my-component {
  margin-bottom: 32px;  /* FALSCH */
}
✓
Richtig: Spacing-Token oder Parent-Gap
.my-layout {
  display: flex;
  flex-direction: column;
  gap: var(--fnd-spacing-component);
}

3. Komponente setzt eigenes Outer-Margin

❌
Falsch: Margin direkt auf der Komponente
.nc-card {
  margin-bottom: var(--fnd-spacing-08);  /* FALSCH */
}
✓
Richtig: Komponenten sind margin-frei, Parent steuert
.card-grid {
  display: grid;
  gap: var(--fnd-spacing-component);
}
/* .nc-card hat kein margin */

4. Fehlender Section-Wrapper

❌
Falsch: Container ohne Section
<div class="nc-container">
  <div class="o-grid">...</div>
</div>
✓
Richtig: Immer in Section wrappen
<section class="section">
  <div class="nc-container">
    <div class="o-grid">...</div>
  </div>
</section>

5. Organism verschachtelt Organism

❌
Falsch: Header (Organism) in Modal (Organism)
<div class="nc-modal">
  <div class="nc-header">...</div>  <!-- FALSCH -->
</div>
✓
Richtig: Modal-Inhalt besteht aus Molecules/Atoms
<div class="nc-modal">
  <div class="nc-modal__header">...</div>
  <div class="nc-modal__body">
    <!-- Molecules und Atoms -->
  </div>
</div>

6. Token-Schichten mischen

❌
Falsch: Komponente nutzt Primitive direkt
.nc-button {
  background: var(--fnd-color-primary-500);  /* FALSCH */
}
✓
Richtig: Komponente nutzt Component-Token
.nc-button {
  background: var(--nc-button-bg);  /* Component-Token */
}

7. rgba() für Overlays

❌
Falsch: rgba() bricht bei Themes
.overlay {
  background: rgba(0, 0, 0, 0.5);  /* FALSCH */
}
✓
Richtig: color-mix() ist theme-kompatibel
.overlay {
  background: color-mix(in srgb,
    var(--fnd-color-always-dark) 50%,
    transparent);
}

Zusammenfassung

# Anti-Pattern Regel
1 Verschachtelte Container Ein .nc-container pro Section
2 Hardcodiertes Spacing Immer --fnd-spacing-* Tokens verwenden
3 Eigenes Outer-Margin Komponenten sind margin-frei
4 Fehlender Section-Wrapper Container immer in <section> wrappen
5 Organism in Organism Organisms enthalten nur Molecules/Atoms
6 Token-Schichten mischen Komponenten nutzen --nc-*, nie --fnd-* Primitives
7 rgba() für Overlays color-mix(in srgb, ...) verwenden
