Accessibility Referenz

Input Group, Stepper und OTP Input müssen für Tastatur- und Screenreader-Nutzer vollständig bedienbar sein.

Stepper: role="spinbutton"

  • Der Stepper-Input erhält role="spinbutton" für korrektes Screenreader-Verhalten
  • Pflicht-Attribute: aria-valuenow, aria-valuemin, aria-valuemax
  • Ein aria-label beschreibt den Zweck des Steppers (z.B. “Menge”)
  • Die +/- Buttons erhalten aria-label="Wert erhöhen" / "Wert verringern"
  • Keyboard: ArrowUp/ArrowDown zum Ändern des Werts (JS-seitig implementieren)

OTP Input: role="group"

  • Der OTP-Container erhält role="group" mit aria-label="Verifizierungscode"
  • Jede Zelle bekommt ein eigenes aria-label (z.B. “Ziffer 1”, “Ziffer 2”)
  • Erste Zelle: autocomplete="one-time-code" für Browser-Autofill
  • inputmode="numeric" zeigt die Zahlentastatur auf Mobilgeräten
  • Keyboard: Auto-Focus auf nächste Zelle bei Eingabe, Backspace springt zurück (JS-seitig)

Input Group: Addon-Accessibility

  • Rein dekorative Addons (Text-Labels wie “https://”) erhalten aria-hidden="true"
  • Interaktive Addons (Buttons) brauchen aria-label wenn kein sichtbarer Text vorhanden ist
  • Der Input selbst behält volle Tastatur-Zugänglichkeit
  • Addons dürfen den Tab-Flow nicht unterbrechen — nur tatsächlich interaktive Elemente sollten fokussierbar sein

Disabled-State

  • Disabled-Inputs werden mit dem nativen disabled-Attribut markiert
  • Disabled-Buttons erhalten zusätzlich aria-disabled="true"
  • Screenreader kündigen “disabled” automatisch an
  • Focus-Ring wird bei disabled-Elementen nicht angezeigt
