Feature Accordion

Zweispaltiges Layout mit Navigations-Links (links) und aufklappbaren Feature-Kapiteln (rechts). Die linke Spalte dient als Inhaltsverzeichnis; die rechte Spalte enthält scrollbare Detail-Kapitel mit nativen <details>/<summary>-Elementen. Kanonische Klasse: .nc-feature-accordeon (BEM).

Aktiver Navigations-Link

Die Klasse .is-active hebt den ausgewählten Navigations-Eintrag hervor. Sie kann per JavaScript gesetzt werden, wenn gescrollt oder ein Kapitel geklickt wird.

Geöffneter Accordion-Eintrag

Ist ein <details>-Element offen (open-Attribut gesetzt), wechselt das Summary-Indikator-Zeichen von + zu −.

Geöffnetes Element (open)

Inhalt des geöffneten Accordion-Eintrags. Kann Text und Listen enthalten.

  • Listeneinträge möglich
  • Weitere Details hier
Geschlossenes Element

Dieser Inhalt ist verborgen.

Accessibility Referenz

Das Feature-Accordion verwendet native HTML-Elemente für maximale Browserkompatibilität und Barrierefreiheit.

Native <details>/<summary>

  • <details> und <summary> sind von Natur aus zugänglich ohne zusätzliche ARIA
  • Screenreader kündigen den geöffneten/geschlossenen Zustand automatisch an
  • Enter oder Space auf dem <summary> toggelt den Zustand
  • Das Ausblenden des Standard-Markers (::-webkit-details-marker: none) ist rein visuell

Navigations-Links

  • Navigations-Buttons (.nc-feature-accordeon__link) sind native <button>-Elemente
  • Der aktive Button sollte aria-current="true" erhalten
  • Die Liste sollte als <nav> mit aria-label oder als <ul> mit role="list" ausgezeichnet sein
  • Transition-Effekte werden via @include transition(color) gesetzt und respektieren prefers-reduced-motion

Scrollbarer Bereich

  • Der scrollbare rechte Container (overflow-y: auto) sollte tabindex="0" erhalten, damit Tastaturnutzer scrollen können
  • Alternativ kann scroll-snap-type für bessere Bedienbarkeit gesetzt werden
  • Screenreader lesen den Inhalt auch ohne Sichtbarkeit vor; max-height ist nur visuell

Best Practices
