Utility — Accessibility

Barrierefreiheit (WCAG 2.1) im Design System: Die einzige Accessibility-Utility-Klasse ist .u-sr-only. Fokus-Ring, Touch-Fläche und reduzierte Bewegung setzen Bauteile über Mixins in ihrem eigenen SCSS um; Skip-Link und Live-Regionen sind Teil der Bauteile, die sie brauchen. Quelldatei: scss/10-utilities/_a11y.scss.

Screen Reader Only — .u-sr-only

Versteckt Inhalt visuell, hält ihn aber für Screenreader zugänglich. Ersetzt .visually-hidden aus der Visibility-Utility. Wird für zusätzliche Kontextinformationen genutzt, die nur per Screenreader vermittelt werden sollen.

Der “Löschen”-Text ist visuell versteckt, aber im Screenreader lesbar. 
<button aria-label="Dokument löschen">
  <svg aria-hidden="true">...</svg>
  <span class="u-sr-only">Löschen</span>
</button>

ARIA Live Region — aria-live + .u-sr-only

Bereich für dynamische Ankündigungen an Screenreader. Meist ist die Live-Region ein sichtbares Element des Bauteils (z. B. die Trefferzahl einer Liste) mit aria-live="polite" oder aria-live="assertive" und role="status" oder role="alert". Soll sie visuell versteckt sein, bekommt sie .u-sr-only. Eine eigene Klasse .u-live-region gibt es seit 09.10.2026 nicht mehr (sie war regelgleich mit .u-sr-only und ungenutzt). 

<!-- Sichtbar im Bauteil -->
<div class="nc-events__results-count" aria-live="polite" aria-atomic="true"></div>

<!-- Visuell versteckt -->
<div class="u-sr-only" aria-live="polite" role="status">
  <!-- JS schreibt hier dynamisch Text rein -->
</div>

<!-- Sofortige Ankündigung (Fehler, Alarm) -->
<div class="u-sr-only" aria-live="assertive" role="alert"></div>

Skip Link — .nc-shell__skip-link

Überspringt wiederholte Navigation und springt direkt zum Hauptinhalt. Ist standardmäßig offscreen, erscheint aber sichtbar beim Fokus (Tab-Taste). Muss das erste fokussierbare Element der Seite sein. Der Skip-Link gehört zur Shell (.nc-shell__skip-link, Drupal: page.html.twig); die frühere Utility .u-skip-link ist seit 09.10.2026 entfernt. 

<body>
  <a class="nc-shell__skip-link" href="#main-content">Zum Hauptinhalt springen</a>
  <header>...Navigation...</header>
  <main id="main-content">...</main>
</body>

Beim Laden der Seite Tab drücken, um den Skip-Link sichtbar werden zu lassen.

Touch Target — Mixin touch-target

Stellt sicher, dass interaktive Elemente eine minimale Touch-Fläche von 44×44 px haben (WCAG 2.5.8). Besonders wichtig für kleine Icons, die als Buttons fungieren. Das Bauteil bindet das Mixin in seinem SCSS ein; eine Utility-Klasse gibt es nicht (mehr). Die Design-System-Buttons bringen die Fläche bereits mit.

Minimale Touch-Fläche 44×44 px, visuelle Größe kann kleiner sein. 
// Bauteil-SCSS
.nc-menu-toggle {
  @include touch-target;   // min. var(--fnd-touch-target-min) = 44px
}

<button class="nc-menu-toggle" aria-label="Menü öffnen">
  <svg aria-hidden="true">...</svg>
</button>

Focus Ring — Mixin focus-visible-ring

Der systemweite Focus-Ring ist in allen interaktiven Design-System-Bauteilen eingebaut. Eigene interaktive Elemente binden ihn über das Mixin im Bauteil-SCSS ein; die frühere Utility .u-focus-ring ist seit 09.10.2026 entfernt. 

// Bauteil-SCSS
.nc-chip {
  @include focus-visible-ring;   // Outline nur bei Tastaturfokus
}

Focus Ring Tokens

Der Focus-Ring wird ueber Foundation-Tokens gesteuert. Zwei Positionierungsmodi: Offset (aussen, Default) und Inset (innen, fuer overflow-hidden Elemente).

TokenDefaultBeschreibung
--fnd-focus-ring-color var(--fnd-color-text-primary) Farbe der Outline (Theme-aware)
--fnd-focus-ring-width 2px Breite der Outline
--fnd-focus-ring-style solid CSS outline-style
--fnd-focus-offset 2px Abstand nach aussen (Default fuer focus-ring)
--fnd-focus-inset 2px Abstand nach innen (fuer focus-ring-inset)

Mixins: Offset vs. Inset

Default (Offset): Die Outline sitzt ausserhalb des Elements — Standard fuer die meisten interaktiven Elemente. Inset: Die Outline sitzt innerhalb des Elements — fuer Elemente mit overflow: hidden, grosse border-radius-Kanten, Karten, Tabellen-Zellen oder Fullwidth-Buttons. 

// SCSS Mixins

// Default: Outline aussen (offset)
@include focus-ring;             // In :focus-visible verwenden
@include focus-visible-ring;     // Wrapper: wendet focus-ring auf :focus-visible an

// Inset: Outline innen
@include focus-ring-inset;       // In :focus-visible verwenden
@include focus-visible-ring-inset; // Wrapper: wendet focus-ring-inset auf :focus-visible an

// Beispiel: Karte mit overflow:hidden
.my-card {
  overflow: hidden;
  border-radius: var(--fnd-radius-md);

  &:focus-visible {
    @include focus-ring-inset;   // Outline bleibt innerhalb des border-radius
  }
}

Reduced Motion — Mixin reduced-motion

Bauteile mit Bewegung reagieren selbst auf das System-Setting prefers-reduced-motion, über das Mixin in ihrem SCSS. Die frühere Utility .u-reduced-motion (Bewegung pauschal aus) ist seit 09.10.2026 entfernt. 

// Bauteil-SCSS
.nc-slider__track {
  transition: transform var(--fnd-motion-duration-300) ease;

  @include reduced-motion {
    transition: none;
  }
}

Mixins im Bauteil

touch-target setzt min-width/min-height auf var(--fnd-touch-target-min) (44 px, WCAG 2.5.8). focus-visible-ring wendet den systemweiten Focus-Ring auf :focus-visible an (--fnd-focus-offset, 2px aussen). reduced-motion kapselt @media (prefers-reduced-motion: reduce).

Fuer Inset-Variante steht das Mixin focus-ring-inset / focus-visible-ring-inset zur Verfuegung. Es nutzt --fnd-focus-inset (2px innen) und ist ideal fuer Elemente mit overflow: hidden oder grossen Border-Radien.

HTML-Muster

<!-- SR-only Text --> <span class="u-sr-only">Zusätzlicher Kontext für Screenreader</span> <!-- Live Region (polite, visuell versteckt) --> <div class="u-sr-only" aria-live="polite" role="status" aria-atomic="true"></div> <!-- Live Region (assertive, Fehler) --> <div class="u-sr-only" aria-live="assertive" role="alert"></div> <!-- Skip Link (Shell) --> <a class="nc-shell__skip-link" href="#main-content">Zum Hauptinhalt springen</a> /* Touch Target, Focus Ring, Reduced Motion: im Bauteil-SCSS */ .nc-icon-toggle { @include touch-target; @include focus-visible-ring; @include reduced-motion { transition: none; } }

Accessibility-Leitfaden

.u-sr-only und die Mixins sind selbst Accessibility-Werkzeuge. Die folgenden Hinweise beschreiben den korrekten Einsatz.

.u-sr-only — Korrekte Nutzung (WCAG 1.3.1)

  • Verwende .u-sr-only um kontextuellen Text hinzuzufügen, den visuelle Nutzer durch visuellen Kontext verstehen
  • Nicht als Ersatz für aria-label auf interaktiven Elementen — beides kann sinnvoll sein
  • Bei Icon-only-Buttons: .u-sr-only-Text oder aria-label ist Pflicht
  • Niemals wichtige Inhalte dauerhaft per .u-sr-only verstecken — Informationen müssen auch visuell prüfbar bleiben

Live-Regionen — Dynamische Ankündigungen (WCAG 4.1.3)

  • aria-live="polite": Ankündigung wartet bis zur nächsten Sprechpause — für Statusmeldungen (Speichern erfolgreich, Daten geladen)
  • aria-live="assertive": Unterbricht sofort — nur für echte Fehler oder zeitkritische Meldungen
  • Live-Regionen müssen beim Seitenaufbau leer sein; erst später Text via JS einfügen
  • Um erneut anzukündigen: Region erst leeren, dann neuen Text setzen (kurzes Timeout)

Skip-Link (.nc-shell__skip-link) — Skip Navigation (WCAG 2.4.1)

  • Muss das erste fokussierbare Element auf der Seite sein
  • href muss auf ein Element mit passender id zeigen (z.B. <main id="main-content">)
  • Mehrere Skip-Links möglich: Hauptinhalt, Suche, Navigation, Footer
  • Das Ziel-Element (<main>) muss tabindex="-1" haben, damit der Fokus korrekt springt (in manchen Browsern)

Mixin touch-target — Zielgröße (WCAG 2.5.8)

  • Mindestens 44×44 px Touch-Fläche für alle interaktiven Elemente — wichtig auf mobilen Geräten
  • Die sichtbare Größe darf kleiner sein (z.B. ein 16px-Icon); die Touch-Fläche wird unsichtbar vergrößert
  • Alternative: ausreichend Abstand (Spacing) zwischen kleinen Elementen (WCAG 2.5.8 Ausnahme)
  • Nicht nötig, wenn das Element bereits ≥ 44×44 px ist (z.B. Standard-Buttons)

Mixin focus-visible-ring — Sichtbarer Fokus (WCAG 2.4.7 / 2.4.11)

  • Alle interaktiven Elemente müssen einen sichtbaren Fokus-Indikator haben
  • focus-visible-ring verwendet :focus-visible — erscheint nur bei Tastaturnavigation, nicht bei Mausklick
  • Fokus-Ring niemals mit outline: none ohne Ersatz entfernen
  • Für Design-System-Komponenten ist der Fokus-Ring bereits eingebaut; das Mixin ist für eigene Bauteile
