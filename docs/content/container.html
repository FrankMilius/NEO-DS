Container

Layout-Container für Seiteninhalte mit adaptivem, fluid-skalierendem Innenabstand. Der Container zentriert Inhalte, begrenzt die maximale Breite und setzt horizontales Padding mit clamp(). Implementiert als SCSS-Mixin container-padding und als Klassen .nc-container / .nc-container--wide.

Padding opt-out

Mit .no-container-pad kann das Container-Padding für einzelne Bereiche oder ganze Sections abgeschaltet werden (z.B. für Hero-Bereiche direkt in der Section).

KlasseAnwendungEffekt
.no-container-pad am inneren div Auf dem direkten Kind-Div des Block-Wrappers Setzt padding-inline: 0 und --container-pad: 0
.no-container-pad am Block-Wrapper Auf dem Block-Wrapper selbst (Section-Ebene) Alle inneren Divs (außer .full-width) erhalten kein Padding
.full-width am inneren div Opt-out vom Container-Max-Width max-width: 100%, box-sizing: border-box

SCSS Mixin: container-padding

Das Mixin container-padding aus 01-tools/_mixins-layout.scss ist das Fundament aller Container-Klassen und wird systemweit eingesetzt.

EigenschaftWertBeschreibung
margin-inline auto Automatische Zentrierung im Viewport
box-sizing border-box Padding in Breitenberechnung eingeschlossen
padding-inline clamp(16px, 3.5vw, 48px) Fluid: min. 16px (320px VP), max. 48px (1600px VP)
--container-pad clamp(16px, 3.5vw, 48px) CSS Custom Property — spiegelt das Padding für Full-Bleed-Berechnungen wider
padding-inline (≥xxl) 0 Ab 1920px: kein seitliches Padding
max-width (≥xxl) $container-max-width Ab 1920px: max. Breite aus Settings
--container-pad (≥xxl) 0px Full-Bleed-Kinder benötigen dann kein negatives Margin

Full-Bleed Formel

Kinder von .nc-container die aus dem Padding ausbrechen sollen, erhalten folgende Styles automatisch:

EigenschaftWertZweck
padding-inline var(--container-pad, 0px) Eigenes Padding entspricht dem Container-Padding
margin-inline calc(-1 * var(--container-pad, 0px)) Negatives Margin hebt das Container-Padding auf
width calc(100% + (var(--container-pad, 0px) * 2)) Breite wird entsprechend vergrößert

Accessibility Referenz

Container sind reine Layout-Objekte ohne eigene Semantik. Die A11y-Anforderungen ergeben sich aus dem Inhalt, nicht aus dem Container selbst.

Kein semantisches Gewicht

  • Container-Divs (.nc-container) sind Layout-Wrapper ohne semantischen Wert für Screenreader
  • Sie erzeugen keine ARIA-Landmarks — nutze <main>, <nav>, <section> etc. für Landmarks
  • Ein <div class="nc-container"> ist für assistive Technologien unsichtbar

Landmark-Struktur

  • Den Container in einem semantischen Landmark-Element verschachteln: <main>, <header>, <footer>, <section aria-label>
  • Ein <section> erhält erst dann Landmark-Status, wenn es ein aria-label oder aria-labelledby besitzt
  • Landmarks helfen Screenreader-Nutzern beim übergeordneten Seitennavigation

Skip-Link

  • Der Haupt-Inhaltsbereich (<main>) sollte per Skip-Link erreichbar sein (id="main-content")
  • Skip-Links helfen Tastatur- und Screenreader-Nutzern, Navigations-Wiederholungen zu überspringen (WCAG 2.4.1)

Fokusverwaltung bei dynamischen Inhalten

  • Wenn Container-Inhalte dynamisch geändert werden (Single-Page-Routing), sollte der Fokus manuell auf den Hauptinhalt gesetzt werden
  • Seiteninhaltswechsel sollten mit aria-live-Regionen oder Fokus-Management begleitet werden
  • Container selbst haben keinen Tabindex — niemals tabindex="0" auf reine Layout-Divs setzen
