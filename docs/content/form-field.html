Form Field

Universeller Wrapper für Label + Input + Hint + Error. Kombiniert alle Form-Bestandteile zu einer zusammenhängenden Einheit. Kanonische Klasse: .nc-form-field (BEM). Enthält .nc-form-label, .nc-form-hint und .nc-form-error.

Wähle Theme, Input-Typ, State und Optionen, um das Form Field live zu konfigurieren.

Default Form Field

Standard-Aufbau: Label, optionaler Hint, Input und optionale Error-Message. Vertikal gestapelt.

Mindestens 3 Zeichen, nur Buchstaben und Zahlen.

Error State

Modifier .nc-form-field--error propagiert den Fehlerstatus auf den enthaltenen Input und zeigt die .nc-form-error Nachricht an.

Bitte geben Sie eine gültige E-Mail-Adresse ein.

Horizontal Layout

Mit .nc-form-field--horizontal werden Label und Input nebeneinander angeordnet (ab Tablet-Breakpoint).

Verschiedene Input-Typen

Das Form Field funktioniert mit allen Eingabetypen: Input, Textarea und Select.

Maximal 500 Zeichen.

DOM-Hinweise

  • Flex-Column-Container der Label, Input, Hint und Error zusammenfasst.
  • gap via --nc-form-field-gap (4px) — Label margin-bottom wird auf 0 gesetzt.
  • Error-Modifier propagiert border-color auf Kind-Inputs (nc-input, nc-textarea, nc-select).
  • Success-Modifier propagiert success-border-color auf Kind-Inputs.
  • Disabled-Modifier graut Label und Hint aus (text-disabled, cursor: not-allowed).
  • Horizontal-Modifier: flex-direction: row ab Tablet, Label 200px breit, Input flex: 1.
  • Hint kann vor oder nach dem Input platziert werden.
  • Input hat aria-describedby mit IDs von Hint und/oder Error (Leerzeichen-getrennt).
  • Required: .nc-form-label__required zeigt '*' (aria-hidden='true'). Der Input bekommt required oder aria-required='true'.
  • Optional: .nc-form-label__optional zeigt '(Optional)' — optionaler visueller Hinweis.
  • Fieldset-Gruppierung: Wenn mehrere Form-Fields zusammengehoeren (z.B. Adresse), wird ein <fieldset> mit <legend> statt <div> verwendet. Siehe fieldset-recipe fuer Details.

Accessibility Referenz

Form-Field ist ein Layout-Wrapper ohne eigene ARIA-Rolle. Accessibility liegt auf den Kind-Elementen: Label (for), Input (aria-describedby, aria-invalid, aria-required), Error (role='alert'), Hint (id).

Nicht interaktiv

  • Diese Komponente ist nicht fokussierbar und nicht klickbar.

Farbkontrast: WCAG AA normal text (4.5:1)

  • Alle Farbvarianten erfüllen dieses Kontrastziel im Default-Theme.
  • Bei Custom-Überschreibungen den Kontrast manuell prüfen.

Zugänglicher Name erforderlich

  • Komponente muss einen zugänglichen Namen haben (via Text-Inhalt, aria-label oder aria-labelledby).

Wenn: requirement = required

  • Empfohlen: aria-required
  • Empfohlen: required
  • Required: Kind-Input braucht required-Attribut oder aria-required='true'. Das Sternchen '*' im Label hat aria-hidden='true' — Screen Reader liest aria-required am Input statt das visuelle Zeichen.

Wenn: validation = error

  • Empfohlen: aria-invalid
  • Error-State: Kind-Input braucht aria-invalid='true'. Error-Message via aria-describedby verknuepft.

Wenn: validation = error + requirement = required

  • Empfohlen: aria-invalid
  • Empfohlen: aria-required
  • Required + Error: Input braucht sowohl aria-invalid='true' als auch required/aria-required='true'. Error-Message erklaert, warum das Pflichtfeld nicht valide ist.

Wenn: Spezialbedingung

  • Disabled-State: Kind-Input hat disabled-Attribut oder aria-disabled='true'.

Wenn: grouping = fieldset

  • Empfohlen: fieldset
  • Empfohlen: legend
  • Fieldset-Gruppierung: Root-Element wird zu <fieldset>, Label-Slot wird zu <legend>. Semantische Gruppierung fuer Screen Reader. Kein aria-labelledby noetig wenn <legend> vorhanden.

Sub-Komponente: Form Label

Accessibility Referenz

<label for='input-id'> verknuepft Label mit Input. Klick auf Label fokussiert den Input. Required-Sternchen ist aria-hidden='true' — Pflichtfeld wird via aria-required='true' am Input kommuniziert. Klickbereich erfuellt WCAG 2.5.8 Target Size (24x24 Minimum).

Nicht interaktiv

  • Diese Komponente ist nicht fokussierbar und nicht klickbar.

Farbkontrast: WCAG AA normal text (4.5:1)

  • Alle Farbvarianten erfüllen dieses Kontrastziel im Default-Theme.
  • Bei Custom-Überschreibungen den Kontrast manuell prüfen.

Zugänglicher Name erforderlich

  • Komponente muss einen zugänglichen Namen haben (via Text-Inhalt, aria-label oder aria-labelledby).

Wenn: indicator = required

  • Empfohlen: aria-hidden
  • Required-Indikator ('*') muss aria-hidden='true' haben. Pflichtfeld-Semantik liegt auf dem Input (aria-required='true').

Wenn: indicator = info

  • Empfohlen: aria-label
  • Empfohlen: aria-describedby
  • Info-Icon ist ein <button> mit aria-label='Hilfe zu {Feldname}'. Tooltip-Inhalt ist via aria-describedby verknuepft oder wird als role='tooltip' angezeigt. Icon selbst ist aria-hidden='true' — der Button traegt den Accessible Name.

Wenn: Spezialbedingung

  • Disabled-Label benoetigt keine eigene ARIA-Annotation — der Disabled-State liegt auf dem Input. Info-Button erhaelt tabindex='-1' und aria-disabled='true'.

Sub-Komponente: Form Hint

Accessibility Referenz

Hint-Text wird via aria-describedby am Input referenziert (id='hint-{name}'). Rein informativ, kein role noetig. Icon ist dekorativ (aria-hidden='true').

Nicht interaktiv

  • Diese Komponente ist nicht fokussierbar und nicht klickbar.

Farbkontrast: WCAG AA normal text (4.5:1)

  • Alle Farbvarianten erfüllen dieses Kontrastziel im Default-Theme.
  • Bei Custom-Überschreibungen den Kontrast manuell prüfen.

Zugänglicher Name erforderlich

  • Komponente muss einen zugänglichen Namen haben (via Text-Inhalt, aria-label oder aria-labelledby).

Wenn: content = with-link

  • Empfohlen: focusVisible
  • Empfohlen: contrast-link
  • Links innerhalb des Hints muessen :focus-visible mit focus-ring haben. Link-Farbe (interactive-default) muss WCAG AA 4.5:1 gegen den Hintergrund erfuellen. Underline ist Pflicht oder per :hover sichtbar.

Wenn: content = list

  • Listen im Hint benoetigen keine zusaetzliche ARIA-Annotation. Die <ul> Semantik genuegt. Bei dynamischen Listen (z.B. Passwort-Regeln die sich abhaaken) kann aria-live='polite' auf dem Hint-Container sinnvoll sein.

Wenn: variant = muted

  • Empfohlen: contrast-muted
  • Muted-Farbe (text-tertiary) muss trotz reduzierter Prominenz 4.5:1 Kontrast einhalten. Im Dark Mode pruefe, ob die Farbe noch lesbar ist.
