Form Field

Token-basierter Form-Field-Wrapper der Label, Input/Textarea/Select, Hint und Error zusammenfügt. Propagiert Validation-States auf Kind-Inputs und unterstützt vertikales und horizontales Layout. Kanonische Klasse: .nc-form-field (BEM). Alle Werte kommen aus --nc-form-field-* Component-Tokens.

Verwendung

Der Form-Field-Wrapper ist der Standard-Container für einzelne Formular-Felder. Er stellt konsistente Abstände zwischen Label, Input, Hint und Error sicher und propagiert Validation-States.

Minimal (Label + Input)

<div class="nc-form-field">
  <label class="nc-form-label" for="name">Name</label>
  <input class="nc-input" type="text" id="name" />
</div>

Mit Hint

<div class="nc-form-field">
  <label class="nc-form-label" for="email">E-Mail</label>
  <input class="nc-input" type="email" id="email" aria-describedby="hint-email" />
  <span class="nc-form-hint" id="hint-email">Wir senden Ihnen eine Bestätigung.</span>
</div>

Vollständig (Label + Hint + Input + Error)

<div class="nc-form-field nc-form-field--error">
  <label class="nc-form-label" for="password">
    <span class="nc-form-label__text">Passwort</span>
    <span class="nc-form-label__required" aria-hidden="true">*</span>
  </label>
  <span class="nc-form-hint" id="hint-pw">Mindestens 8 Zeichen.</span>
  <input class="nc-input" type="password" id="password"
         required aria-invalid="true"
         aria-describedby="hint-pw error-pw" />
  <div class="nc-form-error" role="alert" id="error-pw">
    <span class="nc-form-error__icon" aria-hidden="true">...</span>
    <span class="nc-form-error__text">Passwort muss mindestens 8 Zeichen lang sein.</span>
  </div>
</div>

Horizontal (Label links, Input rechts)

Ab Tablet-Breakpoint: Label 200px breit links, Input nimmt den restlichen Platz ein.

<div class="nc-form-field nc-form-field--horizontal">
  <label class="nc-form-label" for="company">Firma</label>
  <input class="nc-input" type="text" id="company" />
</div>

Validation States

<!-- Error -->
<div class="nc-form-field nc-form-field--error">...</div>

<!-- Success -->
<div class="nc-form-field nc-form-field--success">...</div>

<!-- Disabled -->
<div class="nc-form-field nc-form-field--disabled">
  <label class="nc-form-label">...</label>
  <input class="nc-input" disabled />
</div>

DOM-Hinweise

  • Flex-Column-Container der Label, Input, Hint und Error zusammenfasst.
  • Gap via --nc-form-field-gap (4px) — Label margin-bottom wird auf 0 gesetzt.
  • Error-Modifier propagiert border-color auf Kind-Inputs (nc-input, nc-textarea, nc-select).
  • Horizontal-Modifier: flex-direction: row ab Tablet, Label 200px breit, Input flex: 1.
  • Hint kann vor oder nach dem Input platziert werden.
  • Input hat aria-describedby mit IDs von Hint und/oder Error (Leerzeichen-getrennt).
  • Required: .nc-form-label__required zeigt ‘*’ (aria-hidden="true"). Der Input bekommt required oder aria-required="true".

Accessibility Referenz

Form-Field ist ein Layout-Wrapper ohne eigene ARIA-Rolle. Accessibility liegt auf den Kind-Elementen: Label (for), Input (aria-describedby, aria-invalid, aria-required), Error (role="alert"), Hint (id).

Farbkontrast: WCAG AA normal text (4.5:1)

  • Alle Farbvarianten erfüllen dieses Kontrastziel im Default-Theme.

Wenn: Required

  • Pflicht: Kind-Input braucht required oder aria-required="true".
  • Sternchen ‘*’ im Label hat aria-hidden="true" — Screen Reader liest aria-required am Input.

Wenn: Validation = Error

  • Pflicht: Kind-Input braucht aria-invalid="true".
  • Pflicht: Error-Message via aria-describedby verknüpft.

Wenn: Disabled

  • Kind-Input hat disabled-Attribut oder aria-disabled="true".
