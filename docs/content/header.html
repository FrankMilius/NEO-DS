Header

Haupt-Navigation des globalen Seitenrahmens — fixiert, theme-sensitiv und vollständig responsiv. Der Header beinhaltet die Markenidentität (Nav Brand), die Haupt-Navigation mit optionalen Dropdown-Panels (Nav Drop), Utility-Aktionen (Nav Tools) sowie eine separate Conversion-CTA. Kanonische Klasse: .header. Alle Farbwerte kommen aus --fnd-color-* Foundation-Tokens.

Anatomie

Der Header besteht aus fünf Hauptteilen, die unabhängig voneinander konfiguriert werden können.

.nav-wrapper

Fixierter Container für die gesamte Navigation. Hintergrund: --fnd-color-background-base. Unterrand: --fnd-color-border-low. Klasse .nav-hidden blendet ihn aus (opacity: 0, pointer-events: none).

.nav-brand

Logo + optionaler Subline-Text. Farbe: --fnd-color-text-high. Trenner (zweiter <p>): Linksrand mit --fnd-color-border-low.

.main-nav

Horizontale (Desktop) oder vertikale (Mobile) Linkliste. Hover/Focus-Unterrand: --fnd-color-border-high. Inaktive Links: --fnd-color-text-state-disabled.

.nav-drop

Dropdown-Trigger-Button + zugeordnetes <ul>-Panel. Auf Desktop: fixiertes Full-Bleed-Grid-Panel (12 Spalten, min-height 348px), ein- und ausgeblendet über Opacity/Visibility-Transition. Button-Farbe: --fnd-color-text-high.

.nav-tools

Enthält Icon-Buttons und Hamburger. Icon-Button-Hintergrund: --fnd-color-background-secondary, Hover: --fnd-color-background-tertiary. Hamburger-Icon-Farbe: --fnd-color-text-mid.

.conversion / .cloned-cta

Fixierter Conversion-Button, rechts oben. Positioniert sich über Breakpoint-spezifische margin-inline-Werte aus den Foundation-Spacing-Tokens. .cloned-cta ist eine JS-geklonte Kopie mit höherem Z-Index (3).

Nav Drop — Dropdown-Zustände

Das Dropdown-Panel ist auf Desktop via aria-expanded gesteuert. Auf Mobile wird das zugeordnete <ul> per display: block sichtbar.

<!-- Geschlossen (Standard) --> <li class="nav-drop"> <button aria-expanded="false"> <span>Produkte</span> <span class="icon-only"><!-- Chevron-Down --></span> <span class="icon-only"><!-- Chevron-Up (hidden) --></span> </button> <ul>...</ul> </li> <!-- Geöffnet --> <li class="nav-drop"> <button aria-expanded="true">...</button> <ul><!-- visible: opacity 1, visibility visible --></ul> </li>

Mobile Expanded State

Wenn der Hamburger-Button aktiviert wird, erhält .header die Klasse .expanded. Das Nav-Menu wird sichtbar, der CTA fixiert sich am unteren Bildschirmrand.

<!-- Collapsed --> <header class="header"> <div class="nav-wrapper">...</div> </header> <!-- Expanded (Mobile-Menu offen) --> <header class="header expanded"> <div class="nav-wrapper"> <nav> <div class="nav-brand">...</div> <div class="nav-menu"><!-- sichtbar --></div> <div class="nav-tools"><!-- Hamburger zeigt X-Icon --></div> </nav> </div> </header>

Accessibility Referenz

Der globale Header muss als primäre Navigation vollständig per Tastatur bedienbar und von Screenreadern korrekt verstanden werden. Die folgenden Anforderungen orientieren sich an WCAG 2.1 AA.

Landmarks und Semantik

  • <header> definiert das globale Banner-Landmark — Screenreader können direkt dorthin navigieren
  • <nav> definiert ein Navigation-Landmark und sollte ein aria-label tragen (z.B. aria-label="Hauptnavigation"), wenn mehrere <nav>-Elemente auf der Seite vorhanden sind
  • Das Dropdown-<ul> sollte über aria-controls und eine passende id mit dem Trigger-Button verknüpft sein
  • Verschachtelte <ul>-Listen innerhalb von .main-nav folgen der natürlichen semantischen Listenhierarchie

Dropdown-Tastatursteuerung

  • Dropdown-Buttons müssen aria-expanded="false" (geschlossen) bzw. aria-expanded="true" (geöffnet) führen
  • Enter und Space öffnen/schließen das Dropdown
  • Escape schließt das geöffnete Dropdown und gibt den Fokus an den Trigger zurück
  • Tab-Fokus muss durch alle Links im Dropdown-Panel führen und das Panel korrekt schließen, wenn der Fokus das Panel verlässt
  • Dropdown-Buttons haben :focus-visible: Text-Unterstrich statt Box-Shadow (text-decoration-thickness: 2px, text-underline-offset: 6px)

Hamburger-Button (Mobile)

  • Muss aria-expanded und aria-controls (verweist auf .nav-menu ID) tragen
  • Muss ein sichtbares aria-label haben, das den aktuellen Zustand beschreibt: z.B. aria-label="Navigation öffnen" / aria-label="Navigation schließen"
  • Das Icon wechselt visuell zwischen Hamburger und X — der zugehörige Text muss per aria-label oder aria-live kommuniziert werden
  • Nach dem Öffnen des Menus sollte der Fokus ins Menü verschoben werden (erster fokussierbarer Link)
  • Nach dem Schließen kehrt der Fokus zum Hamburger-Button zurück

Logo und Nav Brand

  • Das Logo-SVG muss entweder ein aria-label am Link (<a aria-label="Zur Startseite">) tragen oder das SVG muss einen <title> enthalten
  • Das SVG selbst sollte aria-hidden="true" tragen, wenn der Link bereits beschriftet ist
  • Logo-SVGs und Icon-Logo-Klassen sind rein dekorativ innerhalb eines beschrifteten Links
  • Separate Produktname-Links müssen ebenfalls einen aussagekräftigen Linktext haben

Icon-Buttons in Nav-Tools

  • Alle .icon-button-Elemente müssen ein aria-label tragen, das die Funktion beschreibt (z.B. aria-label="Suche", aria-label="Konto")
  • Das enthaltene Icon (<span class="icon"> / SVG) muss aria-hidden="true" haben
  • overflow: hidden auf .icon-button span versteckt keinen sichtbaren Text — nur Clippen von Icon-Overflows
  • Fokus-Indikator: Icon-Buttons müssen einen sichtbaren :focus-visible-Ring erhalten (via @include focus-ring oder äquivalent)

Inaktive Links (.inactive)

  • Farbe: --fnd-color-text-state-disabled — muss ausreichend Kontrast gegenüber dem Hintergrund bieten (min. 3:1 für UI-Komponenten, WCAG 1.4.11)
  • Inaktive Elemente sollten zusätzlich aria-disabled="true" tragen, wenn sie nicht navigierbar sind
  • Rein visuell deaktivierte Links (ohne disabled-Attribut) bleiben im Tab-Fokus — das ist akzeptabel, solange sie klar als inaktiv kommuniziert werden
