Buttons

Token-basierte Button-Komponente mit 10 Varianten in 3 Gruppen (Main, Supporting, System), 4 Größen, fester Typography und Icon-Support. Kanonische Klasse: .nc-button (BEM). Alle Werte kommen aus --nc-button-* Component-Tokens.

DOM-Hinweise

  • Buttons muessen immer ein zugaengliches Label haben — entweder sichtbarer Text oder aria-label fuer Icon-Only.
  • Spinner (.nc-button__spinner) wird im State 'loading' angezeigt und blockiert Interaktion: Modifier .nc-button--loading plus aria-busy='true' — erst der Modifier zeichnet den Spinner.
  • XS/SM Buttons haben unsichtbaren ::before Touch-Target (44px Minimum, WCAG 2.5.8).
  • Loading nutzt visibility:hidden statt opacity:0 — Label-Breite bleibt erhalten, kein Layout-Shift.

Accessibility Referenz

Buttons muessen immer ein zugaengliches Label haben — entweder sichtbarer Text oder aria-label fuer Icon-Only.

Farbkontrast: WCAG AA normal text (4.5:1)

  • Alle Farbvarianten erfüllen dieses Kontrastziel im Default-Theme.
  • Bei Custom-Überschreibungen den Kontrast manuell prüfen.

Fokus-Indikator

  • focus-ring mixin, :focus-visible

Zugänglicher Name erforderlich

  • Komponente muss einen zugänglichen Namen haben (via Text-Inhalt, aria-label oder aria-labelledby).

Wenn: pattern = icon-only

  • Pflicht: aria-label
  • Kontrastziel: WCAG AA non-text (3:1)
  • Icon-Only Buttons benoetigen immer aria-label. Quadratische Flaeche fuer einfaches Treffen.

Wenn: size = xs, sm

  • XS/SM erhalten ::before Touch-Target (44px) fuer WCAG 2.5.8 Target Size.

Wenn: composition = group

  • Empfohlen: role=group
  • Empfohlen: aria-label=Aktionen
  • Button-Group benoetigt role='group' mit aria-label. Mittlere Buttons haben keinen Radius.

Wenn: composition = toggle

  • Pflicht: aria-pressed
  • Toggle-Buttons muessen aria-pressed verwenden. Aktiver Zustand kann zu Primary-Farben wechseln (Resolver-Regel).

Wenn: composition = fab

  • Pflicht: aria-label
  • FAB benoetigt aria-label da kein sichtbarer Text vorhanden. Elevation-Shadow signalisiert interaktive Flaeche.

Wenn: composition = link

  • Links als Buttons gestylt benoetigen role='button' und Keyboard-Handling, wenn sie keine Navigation ausloesen.

Wenn: variant = inverted

  • Kontrastziel: WCAG AA normal text (4.5:1)
  • Inverted-Buttons auf dunklen Hintergruenden — Kontrast gegen den tatsaechlichen Hintergrund pruefen, nicht gegen Surface.

Welche Button-Variante?

Entscheidungshilfe für die Wahl der richtigen Button-Variante, -größe und semantischen Rolle.

Varianten-Hierarchie

B1 Primary = Haupt-CTA der Seite/Section

Nur EIN Primary Button pro sichtbarem Viewport. Repräsentiert die wichtigste Aktion (Absenden, Kaufen, Weiter). Maximale visuelle Gewichtung.

B2 Secondary = Zweitwichtigste Aktion

Steht neben dem Primary als Alternative (z.B. „Mehr erfahren“ neben „Jetzt starten“). Geringere visuelle Gewichtung, gleiche Größe.

B3 Tertiary / Ghost / Outline = Untergeordnete Aktionen

Tertiary: Reduzierte Fläche, für Cancel, Zurück, optionale Aktionen. Ghost: Minimal, nur Text+Hover. In Toolbars, Inline-Aktionen. Outline: Mit Rahmen, für sekundäre Aktionen mit klarer Begrenzung.

B4 System-Varianten (Success/Error/Warning/Info)

Success: Bestätigende Aktionen (Speichern, Bestätigen). Error: Destruktive Aktionen (Löschen, Abbrechen) — immer mit Confirmation! Warning: Aktionen mit Nebeneffekten (Zurücksetzen, Überschreiben). Info: Informative Aktionen (Details anzeigen, Hilfe).

B5 Icon-Only vs. Text-Button

Icon-Only nur wenn das Icon universell verständlich ist (Schließen, Suche, Menü) UND Platz begrenzt ist. Immer aria-label setzen. Sonst: Icon + Text kombinieren.

B6 Button vs. Link Semantik

<button>: Löst eine Aktion aus (Submit, Toggle, Dialog öffnen). <a href>: Navigiert zu einer URL. Auch wenn es wie ein Button aussieht → Verweis auf Komponenten-Matrix R1.

Entscheidungsbaum: Varianten-Wahl

1 Ist es die wichtigste Aktion im Viewport?
Ja
Primary Haupt-CTA, max. 1 pro Viewport
Nein ↓
2 Hat die Aktion einen semantischen Zustand?
Ja
System-Variante Success / Error / Warning / Info
Nein ↓
3 Braucht der Button eine klare visuelle Begrenzung?
Ja
Secondary Zweit-CTA neben Primary
Outline Eigenständige Aktion mit Rahmen
Nein ↓
4 Minimale visuelle Präsenz gewünscht?
Ja
Tertiary Cancel, Zurück
Ghost Toolbar, Inline, nur bei Hover sichtbar
