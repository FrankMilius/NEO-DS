System Overview

Das NEO Design System ist ein token-basiertes, framework-unabhängiges Designsystem auf Basis von SCSS/CSS und Vanilla JS. Es verbindet Atomic Design mit ITCSS, ein 3-Schichten-Token-Modell mit Recipe-gesteuerter Komponentendefinition und einem 4-Themes-System für Brand- und Dark-Mode-Switching.

Kernprinzipien

  • Token-First: Keine hardcodierten Werte in Komponenten — alle visuellen Eigenschaften laufen über CSS Custom Properties (--fnd-*, --nc-*).
  • Komposition über Vererbung: Layouts und Komponenten werden aus kleinen, wiederverwendbaren Primitiven zusammengesetzt, nicht durch tiefe Klassen-Hierarchien.
  • Recipe-Driven: Jede Komponente wird durch eine strukturierte JSON-Spezifikation (Recipe) definiert — Anatomie, Achsen, States, A11y und Styling sind maschinenlesbar.
  • Theme-Agnostic: Komponenten referenzieren semantische Tokens, nicht Farb-Primitives. Theming geschieht durch Austausch der semantischen Schicht.
  • Framework-Unabhängig: Reines CSS/SCSS + Vanilla JS. Jedes Framework kann die Klassen und Tokens konsumieren.

Was ist ein Recipe?

Ein Recipe ist eine strukturierte JSON-Spezifikation für eine Komponente. Es beschreibt nicht nur das Aussehen, sondern auch Anatomie, Interaktionszustände, Barrierefreiheits-Anforderungen und verfügbare Varianten. Recipes sind die Single Source of Truth für Komponenten — sowohl für die Dokumentation als auch für den Theme Configurator.

Die 9 kanonischen Sektionen

#SektionZweckBeispiel
1metaIdentifikation: ID, Label, Kategorie, Status"id": "button", "category": "atoms"
2anatomyDOM-Struktur: Elemente und BEM-Klassen["root", "icon", "label"]
3axesVarianten-Achsen: Grösse, Variante, Form"variant": ["primary", "secondary", "ghost"]
4statesInteraktionszustände: hover, active, disabled, focus["default", "hover", "active", "disabled"]
5a11yBarrierefreiheit: ARIA-Attribute, Kontrast, Focus"role": "button", "focusRing": true
6stylingToken-Mappings: Welche --nc-* Tokens auf welche CSS-Properties"--nc-button-bg": "background-color"
7recipesKonkrete Ausprägungen: Token-Werte pro Achsen-Kombination"primary-md": { "--nc-button-bg": "..." }
8specimensVorschau-Konfigurationen für den Theme Configurator"default": { "label": "Senden", "icon": "arrow-right" }
9linksExterne Referenzen: Figma, Docs, Storybook"figma": "https://...", "docs": "button-docs.html"

Recipe-Struktur (vereinfacht)

{
  "meta":      { "id": "button", "label": "Button", "category": "atoms" },
  "anatomy":   ["root", "icon", "label"],
  "axes":      { "variant": ["primary","secondary","ghost"], "size": ["sm","md","lg"] },
  "states":    ["default", "hover", "active", "focus", "disabled"],
  "a11y":      { "role": "button", "focusRing": true, "minContrast": 4.5 },
  "styling":   { "--nc-button-bg": "background-color", "--nc-button-color": "color" },
  "recipes":   { "primary-md": { "--nc-button-bg": "var(--fnd-color-interactive-default)" } },
  "specimens": { "default": { "label": "Senden" } },
  "links":     { "docs": "button-docs.html" }
}

4-Themes-System

Das Design System unterstützt vier Themes — zwei Marken (NEO, Customer) jeweils in Light und Dark. Themes werden über die semantische Token-Schicht umgeschaltet, sodass Komponenten keine Theme-spezifische Logik benötigen.

Theme-KlasseMarkeModusAktivierung
.neo-light-themeNEO (Primär)LightDefault
.neo-dark-themeNEO (Primär)Darkdata-theme="neo-dark-theme" oder prefers-color-scheme: dark
.customer-light-themeCustomer (Sekundär)Lightdata-theme="customer-light-theme"
.customer-dark-themeCustomer (Sekundär)Darkdata-theme="customer-dark-theme"

Wie Theming funktioniert

1. Automatisch (System-Präferenz)
   @media (prefers-color-scheme: dark) {
     :root { /* Dark-Semantic-Tokens */ }
   }

2. Manuell (data-theme Attribut)
   <html data-theme="neo-dark-theme">
   → Überschreibt prefers-color-scheme

3. Scoped (Section-Level)
   <section class="neo-dark-theme">
   → Lokaler Dark-Mode für eine Sektion

Brand Injection

Die Customer-Themes werden über Sass-Variablen mit eigenen Markenfarben gespeist. Der Build generiert daraus automatisch die passenden Primitives und Semantic Tokens. 

// _color-primitives.scss
$brand-source: "customer";               // "neo" oder "customer"
$customer-primary-base: #e4002b;          // Marken-Primärfarbe
$customer-secondary-base: #003366;        // Marken-Sekundärfarbe

// Generiert automatisch:
// --fnd-color-primary-100 ... --fnd-color-primary-950  (Customer-Palette)
// --fnd-color-secondary-100 ... --fnd-color-secondary-950

Fluid Tokens via clamp()

Statt fixer Breakpoint-Sprünge nutzt das System clamp() für fliessende Übergänge. Dies gilt für:

  • Typography: --fs-base: clamp(0.875rem, 0.8rem + 0.25vw, 1.125rem) — skaliert von 14px bis 18px
  • Spacing: Stufen 06–13 nutzen clamp() für fluid Spacing
  • Container Padding: clamp(16px, 3.5vw, 48px)
  • Grid Gap: clamp(12px, 1.5vw, 24px)

respond-to() Mixin

// Verwendung
.nc-card {
  flex-direction: column;

  @include respond-to(md) {
    flex-direction: row;    // Ab 768px: horizontal
  }

  @include respond-to(lg) {
    gap: var(--fnd-spacing-08);  // Ab 1024px: grösserer Gap
  }
}
