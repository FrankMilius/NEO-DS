Notification

Seitenbreiter Benachrichtigungs-Banner, der am oberen Rand der Seite klebt (position: sticky). Wird eingesetzt für systemweite Hinweise, Wartungsmeldungen oder wichtige Status-Informationen. Kanonische Klasse: .notification. Sichtbarkeit wird über die Zustands-Klasse .show gesteuert. Alle Farb- und Abstandswerte kommen aus Foundation-Tokens --fnd-*.

Basis

Der Notification-Banner in seiner einfachsten Form — nur mit Text und einem Close-Button. Die Klasse .show macht den Banner sichtbar.

Wartungsfenster: Am Freitag, 21. Februar, von 22:00 bis 02:00 Uhr steht das System nicht zur Verfügung.

Mit Secondary Action

Ein zusätzlicher Link oder Button (.secondary) direkt nach dem Beschreibungstext ermöglicht eine Handlungsaufforderung, z.B. „Mehr erfahren“ oder „Jetzt aktualisieren“. Auf Desktop erscheint er inline, auf Mobile darunter.

Ohne Close-Button

Für Meldungen, die nicht schließbar sein sollen, kann der Close-Button weggelassen werden. Verwendung z.B. bei kritischen Systemhinweisen.

Kritischer Systemfehler: Bitte speichern Sie Ihre Arbeit und laden Sie die Seite neu.

Versteckter Zustand

Ohne die Klasse .show ist der Banner vollständig ausgeblendet (height: 0, opacity: 0, visibility: hidden) und nimmt keinen Platz ein. Er bleibt dabei im DOM und kann per JS jederzeit wieder eingeblendet werden. 

<!-- Banner im DOM, aber nicht sichtbar -->
<div class="notification" role="status" aria-live="polite">
  <div class="notification-body">
    <p>Dieser Banner ist verborgen.</p>
  </div>
</div>

<!-- Banner sichtbar -->
<div class="notification show" role="status" aria-live="polite">
  <div class="notification-body">
    <p>Dieser Banner ist sichtbar.</p>
  </div>
</div>

JavaScript-Steuerung

Die Komponente hat keine eigene JS-API. Die Sichtbarkeit wird ausschließlich über die Klasse .show gesteuert. 

// Banner einblenden
document.querySelector('.notification').classList.add('show');

// Banner ausblenden
document.querySelector('.notification').classList.remove('show');

// Banner schließen via Close-Button
document.querySelector('.notification .icon-button').addEventListener('click', (e) => {
  e.preventDefault();
  e.currentTarget.closest('.notification').classList.remove('show');
});

Accessibility

Die Notification-Komponente folgt dem WAI-ARIA Alert Pattern und nutzt Live-Regions, damit Screenreader-Nutzer den Banner-Inhalt auch ohne visuelle Wahrnehmung erhalten.

ARIA-Rollen & Attribute

Element Attribut Beschreibung
Banner (.notification)role="status"Für informative Meldungen (polite) — unterbricht Screenreader nicht
Banner (.notification)role="alert"Für dringende Meldungen (assertive) — unterbricht Screenreader sofort
Banner (.notification)aria-live="polite"Ergänzt role="status" für maximale Browser-Kompatibilität
Banner (.notification)aria-live="assertive"Ergänzt role="alert" für kritische Meldungen
Close-Button (a.icon-button)aria-label="Schließen"Beschriftung für den Icon-Only-Button
Icon im Close-Button (.icon-only)aria-hidden="true"Icon ist dekorativ — aria-label am Button liefert den Namen

Tastatur-Navigation

Taste Aktion
TabFokussiert den Close-Button oder den Secondary-Link im Banner
Enter / SpaceAktiviert den fokussierten Link oder Button
EscapeOptional per JS: Schliesst den Banner (muss individuell implementiert werden)

role="status" vs. role="alert"

Verwendungsfall Empfehlung Begründung
Informationen, Updates, Neuigkeiten role="status" + aria-live="polite" Screenreader liest beim nächsten Pause-Punkt vor (nicht unterbrechend)
Systemfehler, Datenverlust-Warnung role="alert" + aria-live="assertive" Screenreader unterbricht sofort und liest vor (dringlich)
Wartungsfenster, geplante Abschaltung role="status" + aria-live="polite" Nicht dringend, Nutzer kann zu einem späteren Zeitpunkt handeln
Aktiver Systemausfall, sofortiger Handlungsbedarf role="alert" + aria-live="assertive" Nutzer muss sofort informiert werden, Handlung ist zeitkritisch

Best Practices

  • Der Banner soll genau einmal pro Seite vorhanden sein und am Beginn des <body> stehen, damit er beim Scrollen korrekt klebt.
  • Verwende role="status" für informative Hinweise — role="alert" nur für kritische Meldungen.
  • Der Inhalt des Banners sollte kurz und handlungsorientiert sein (max. 1–2 Sätze).
  • Verwende kein role="alert" für nicht-dringende Inhalte — es unterbricht Screenreader-Nutzer unerwartet.
  • Der Close-Button muss immer ein aria-label="Schließen" besitzen, da er nur ein Icon enthält.
  • Der Secondary-Link (.secondary) muss einen aussagekräftigen Linktext haben — kein „Hier klicken“.
  • Nach dem Schließen des Banners sollte der Fokus nicht verloren gehen — das auslösende Element oder das nächste sinnvolle Element sollte fokussiert werden.
  • Stelle sicher, dass der Text im Banner ausreichend Kontrast zum Hintergrund hat (WCAG 1.4.3: mind. 4,5:1).
  • Die Komponente nutzt visibility: hidden im versteckten Zustand — diese Elemente werden von Screenreadern korrekt ignoriert.

Anti-Patterns

<!-- RICHTIG: Informations-Meldung mit role="status" -->
<div class="notification show" role="status" aria-live="polite">
  <div class="notification-body">
    <p><strong>Wartung:</strong> Das System ist am Freitag von 22–02 Uhr offline.</p>
    <a href="/wartung" class="secondary">Details anzeigen</a>
  </div>
  <a href="#" class="icon-button" aria-label="Schließen">
    <span class="icon-only" aria-hidden="true"><svg>...</svg></span>
  </a>
</div>

<!-- FALSCH: role="alert" für harmlose Meldung -->
<div class="notification show" role="alert">
  <div class="notification-body">
    <p>Neue Version verfügbar.</p>
  </div>
</div>

<!-- FALSCH: Close-Button ohne aria-label -->
<a href="#" class="icon-button">
  <span class="icon-only"><svg>...</svg></span>
</a>

<!-- FALSCH: Nichtssagender Linktext -->
<a href="/changelog" class="secondary">Hier klicken</a>

<!-- FALSCH: Banner mit display:none ausblenden (statt .show entfernen) -->
<div class="notification show" style="display: none;">...</div>
