Alert Dialog

Modaler Bestätigungs-Dialog basierend auf dem nativen <dialog>-Element. Fokus-Trap, ESC-Close und Body-Scroll-Lock sind nativ integriert. Kanonische Klasse: .nc-alert-dialog (BEM). Verwendet --nc-dialog-* Component-Tokens.

Basis Alert Dialog

Kanonische HTML-Struktur eines Alert Dialogs. Der Dialog wird per showModal() geöffnet und ist ein modales Overlay.

<dialog class="nc-alert-dialog" aria-labelledby="dlg-title" aria-describedby="dlg-desc"> <div class="nc-alert-dialog__header"> <h2 class="nc-alert-dialog__title" id="dlg-title">Sind Sie sicher?</h2> <p class="nc-alert-dialog__description" id="dlg-desc"> Diese Aktion kann nicht rückgängig gemacht werden. </p> </div> <div class="nc-alert-dialog__footer"> <button class="nc-button nc-button--outline">Abbrechen</button> <button class="nc-button nc-button--danger" autofocus>Löschen</button> </div> </dialog>

Destructive Confirmation

Ein destruktiver Bestätigungs-Dialog für kritische Aktionen wie das Löschen eines Kontos.

Ohne Beschreibung

Ein vereinfachter Dialog ohne Beschreibungstext — nur Titel und Aktions-Buttons.

JavaScript API

Die native <dialog>-API zum Öffnen, Schließen und Event-Handling.

// Öffnen (modal mit Backdrop + Focus-Trap) const dialog = document.querySelector('.nc-alert-dialog'); dialog.showModal(); // Schließen dialog.close(); // Event: Dialog wurde geschlossen dialog.addEventListener('close', () => { console.log('Dialog geschlossen, returnValue:', dialog.returnValue); }); // Event: ESC gedrückt dialog.addEventListener('cancel', (e) => { // Optional: e.preventDefault() um ESC zu blockieren });

Accessibility Referenz

Der Alert Dialog nutzt das native <dialog>-Element und erfüllt die WCAG 2.1 AA-Kriterien nativ.

Natives <dialog>

  • Automatisch role="dialog" und aria-modal="true" bei showModal()
  • Kein manuelles ARIA-Setup nötig — der Browser übernimmt die korrekte Semantik
  • Unterstützt in allen modernen Browsern (Chrome, Firefox, Safari, Edge)

aria-labelledby / aria-describedby

  • aria-labelledby verlinkt den Dialog mit der Titel-ID (.nc-alert-dialog__title)
  • aria-describedby verlinkt mit der Beschreibungs-ID (.nc-alert-dialog__description)
  • Screenreader lesen beim Öffnen automatisch Titel und Beschreibung vor
  • Ohne Beschreibung: aria-describedby weglassen

Focus-Trap

  • Nativ bei showModal() — Fokus bleibt im Dialog
  • Tab-Navigation zykliert zwischen den interaktiven Elementen innerhalb des Dialogs
  • Elemente außerhalb des Dialogs sind nicht erreichbar (inert)
  • Kein JavaScript-basierter Focus-Trap nötig

ESC-Close

  • Native Tastaturunterstützung — ESC schließt den Dialog
  • Löst das cancel-Event aus, gefolgt vom close-Event
  • Optional: e.preventDefault() im cancel-Event blockiert das Schließen per ESC

Focus-Rückkehr

  • Fokus kehrt automatisch zum Trigger-Element zurück, das den Dialog geöffnet hat
  • Natives Verhalten von <dialog> — kein manuelles Focus-Management nötig
  • Funktioniert sowohl bei close() als auch bei ESC

autofocus

  • Action-Button mit autofocus-Attribut für direkten Keyboard-Zugriff
  • Bei showModal() erhält das Element mit autofocus automatisch den Fokus
  • Ermöglicht sofortige Betätigung per Enter/Space ohne Tab-Navigation

Body-Scroll-Lock

  • CSS-basiert via body:has(.nc-alert-dialog[open]) { overflow: hidden; }
  • Verhindert Hintergrund-Scrollen während der Dialog geöffnet ist
  • Kein JavaScript nötig — rein deklarativ
