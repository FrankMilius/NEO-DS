Accordion

Zusammenklappbare Inhaltsbereiche auf Basis nativer <details>/<summary>-Elemente. Der Accordion blendet Inhalte progressiv ein und aus — ohne JavaScript erforderlich. Kanonische Klasse: .accordion-item. Animierter Modus: [data-accordion] auf dem Content-Element.

Was ist ein Accordion?

Ein Accordion ist ein zusammenklappbares UI-Element, das Inhalt progressiv offenbart. Es eignet sich für FAQ-Seiten, Einstellungsbereiche und umfangreiche Inhalte, die übersichtlich strukturiert werden sollen.

Wann sollte ich einen Accordion verwenden?

Verwende Accordions wenn der Inhalt länger ist als der verfügbare Platz, wenn Benutzer selektiv Informationen benötigen oder wenn hierarchische Informationen übersichtlich präsentiert werden sollen.

Wird JavaScript benötigt?

Nein. Der Accordion funktioniert vollständig ohne JavaScript auf Basis des nativen <details>/<summary>-Elements. Für den animierten Datenzustand wird [data-accordion] am Content-Element gesetzt.

Mit Progress Bar

Die optionale .accordion-progress-Leiste wird auf Desktop-Viewports als horizontale Linie angezeigt. Sie wird mit der Klasse .active aktiviert und durch transform: scaleX(1) sichtbar gemacht.

Item mit aktiver Progress Bar

Die Progress Bar (.accordion-progress.active) erscheint als 1px-Linie am oberen Rand des Items. Sie wird typischerweise per JavaScript gesteuert, um den Fortschritt in einem Onboarding-Ablauf anzuzeigen.

Item mit inaktiver Progress Bar

Ohne die .active-Klasse bleibt die Progress Bar unsichtbar (transform: scaleX(0)).

Register (.nc-accordion--register)

Zweispaltig, für Listen, in denen man sucht statt liest — Glossare, Integrationen, Downloads. Halbiert die Bauhöhe bei vielen kurzen Einträgen. Ab etwa acht Einträgen sinnvoll. Unterhalb der Umbruchbreite bleibt eine Spalte: Zwei Spalten auf einem Telefon heißen zwei Anfänge auf 180 px Breite.

Nicht einsetzen, wenn die Reihenfolge etwas bedeutet. Zwei Spalten heißen zwei Leseanfänge; eine Schrittfolge wird darin unlesbar. Ein Medium neben dem Text ist hier wirkungslos — die Spalte ist zu schmal, deshalb fällt --media-side in der Registerfassung auf --media-top zurück.

Umgesetzt als CSS-Grid und nicht als column-count: Spalten würden einen Eintrag an der Spaltengrenze zerlegen, sobald er aufklappt. Die Spaltenzahl hängt an --nc-accordion-register-columns.

Lesefassung (.nc-accordion--lese)

Volle Breite, große Auslöser, Medium im Textfluss. Kein Beiwerk neben einem Kopf, sondern ein Abschnitt, der selbst gelesen wird — Schrittfolgen, Ratgeber, längere Erklärstücke. Drei bis fünf Einträge mit je mehreren Sätzen.

Das Medium ist hier der Punkt und nicht die Beigabe, deshalb gilt eine eigene, großzügigere Höhendeckelung (--nc-accordion-lese-media-max). Begrenzt wird die Höhe, die Breite folgt der Form des Bildes: Ein hochkantes Bild wird zu einer ruhigen Spalte statt zu einem Band mit abgeschnittenem Kopf.

Nicht für FAQ. Dort ist --flush schneller. Und Nummern im Kicker nur, wenn es wirklich eine Folge ist — sonst behaupten sie eine Ordnung, die es nicht gibt.

Anschnittlinie

Bei --flush, --ghost, --register und --lese beginnt der Text auf der Spaltenkante: Das Innenpolster wandert aus dem Textfluss, das Zeichen hängt im Bund.

Gemessen am 20.08.2026 vor der Korrektur bei 1440 px: Sektionskopf bei 73 px, Auslöser bei 771, Inhalt bei 767 — die beiden standen weder mit dem Kopf noch miteinander auf einer Linie.

Die Kartenfassungen behalten ihr Polster. Bei --separated und --elevated ist es die Fläche des Gegenstands und keine Nachlässigkeit.

Sprungziele

Jeder Eintrag trägt eine Kennung; /seite#kennung öffnet ihn und springt hin. Der so geöffnete Eintrag bekommt eine Marke (:target), damit man sieht, wo man gelandet ist.

Ein <details> mit passender id ist zwar das Sprungziel des Browsers, bleibt aber zu — gesprungen wird an eine Überschrift, unter der nichts steht. Aufklappen muss das Skript.

Warum <details>

Bei einem Akkordeon ohne äußeres Medium kann das native Element alles, was gebraucht wird — inklusive „genau eines offen“ über das name-Attribut. Und es kann etwas, das eine Nachbildung aus button und aria-expanded nicht kann: Die Browsersuche findet Text in einem zugeklappten <details> und klappt ihn selbst auf.

Die Gegenprobe steht in der Geräte-Strecke (.nc-product-showcase--accordion): Dort muss es ein <button> sein, weil gleichzeitig ein Medium außerhalb wechselt. Das kann <details> nicht.

Beim Drucken klappt @media print alles auf und blendet Zeichen und Schalter aus. Ein zugeklapptes Akkordeon druckt sonst eine Liste von Überschriften ohne Inhalt — und das merkt niemand, bis das Blatt aus dem Drucker kommt.

Animierter Inhalt ([data-accordion])

Das data-accordion-Attribut schaltet die Opacity-Animation ein. Auf Desktop-Viewports wird ein Content-Bereich ohne die Klasse .show ausgeblendet (opacity: 0, pointer-events: none). Mit .show wird er sichtbar und klickbar.

Dieser Bereich hat data-accordion + .show — er ist sichtbar und klickbar.

DOM-Hinweise

  • Kann als natives <details>/<summary> oder als ARIA-Pattern (role='region') implementiert werden.
  • BEM: .nc-accordion > .nc-accordion__item > .nc-accordion__trigger + .nc-accordion__content > .nc-accordion__content-inner.
  • CSS-Grid-Animation: .nc-accordion__content nutzt grid-template-rows: 0fr → 1fr fuer fluessige Hoehen-Animation ohne feste Pixelwerte.
  • Trigger versteckt den nativen details-marker via list-style:none und ::-webkit-details-marker.
  • Icon rotiert bei open-State (transform: rotate(180deg)).
  • Content-inner hat overflow:hidden — bei 0fr wird Content clipped, bei 1fr sichtbar.
  • Media-Slot: Optionaler Bild/Video-Container innerhalb content-inner. Layout via --media-top oder --media-side Modifier.
  • Separated-Variante: Items als eigenstaendige Cards mit Gap, Border-Radius, Shadow.
  • Elevated-Variante: Geoeffnetes Item bekommt staerkeren Schatten (z-index: 1, position: relative).
  • Ghost-Variante: Keine Borders/BG, nur Text + Icon. Hover zeigt dezenten Hintergrund mit border-radius.
  • prefers-reduced-motion: Transitions werden deaktiviert.
  • Legacy: .accordion-item / .accordion-item-summary (non-BEM, migriert von solutions.css) — am Ende der SCSS-Datei erhalten.

Accessibility Referenz

Natives <details>/<summary> ist inhaerent accessible. Alternativ: button + aria-expanded + aria-controls. Trigger ist per Tab erreichbar, Enter/Space toggelt.

Farbkontrast: WCAG AA normal text (4.5:1)

  • Alle Farbvarianten erfüllen dieses Kontrastziel im Default-Theme.
  • Bei Custom-Überschreibungen den Kontrast manuell prüfen.

Zugänglicher Name erforderlich

  • Komponente muss einen zugänglichen Namen haben (via Text-Inhalt, aria-label oder aria-labelledby).

Wenn: behavior = single

  • Single-Mode: HTML5 details[name] Attribut (gleicher Name = exclusiv). Oder JS mit aria-expanded Steuerung.

Wenn: Spezialbedingung

  • Empfohlen: aria-disabled
  • Disabled Items: aria-disabled='true' auf dem Trigger. Pointer-events: none.

Wenn: media-layout = top, side

  • Pflicht: aria-hidden-media
  • Media-Bilder sind dekorativ (aria-hidden='true'). Alt-Text nur bei informativem Bildinhalt.
