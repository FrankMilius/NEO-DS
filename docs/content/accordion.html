Accordion

Zusammenklappbare Inhaltsbereiche auf Basis nativer <details>/<summary>-Elemente. Der Accordion blendet Inhalte progressiv ein und aus — ohne JavaScript erforderlich. Kanonische Klasse: .accordion-item. Animierter Modus: [data-accordion] auf dem Content-Element.

Was ist ein Accordion?

Ein Accordion ist ein zusammenklappbares UI-Element, das Inhalt progressiv offenbart. Es eignet sich für FAQ-Seiten, Einstellungsbereiche und umfangreiche Inhalte, die übersichtlich strukturiert werden sollen.

Wann sollte ich einen Accordion verwenden?

Verwende Accordions wenn der Inhalt länger ist als der verfügbare Platz, wenn Benutzer selektiv Informationen benötigen oder wenn hierarchische Informationen übersichtlich präsentiert werden sollen.

Wird JavaScript benötigt?

Nein. Der Accordion funktioniert vollständig ohne JavaScript auf Basis des nativen <details>/<summary>-Elements. Für den animierten Datenzustand wird [data-accordion] am Content-Element gesetzt.

Standardmäßig geöffnet

Das open-Attribut am <details>-Element öffnet ein Item beim Laden der Seite.

Dieses Item ist standardmäßig geöffnet

Das open-Attribut am <details>-Element bewirkt, dass der Inhalt beim Seitenaufruf sichtbar ist. Der Benutzer kann es jederzeit schließen.

Dieses Item ist geschlossen

Inhalt dieses geschlossenen Items. Der Benutzer kann es durch Klick auf den Summary-Bereich öffnen.

Mit Progress Bar

Die optionale .accordion-progress-Leiste wird auf Desktop-Viewports als horizontale Linie angezeigt. Sie wird mit der Klasse .active aktiviert und durch transform: scaleX(1) sichtbar gemacht.

Item mit aktiver Progress Bar

Die Progress Bar (.accordion-progress.active) erscheint als 1px-Linie am oberen Rand des Items. Sie wird typischerweise per JavaScript gesteuert, um den Fortschritt in einem Onboarding-Ablauf anzuzeigen.

Item mit inaktiver Progress Bar

Ohne die .active-Klasse bleibt die Progress Bar unsichtbar (transform: scaleX(0)).

Animierter Inhalt ([data-accordion])

Das data-accordion-Attribut schaltet die Opacity-Animation ein. Auf Desktop-Viewports wird ein Content-Bereich ohne die Klasse .show ausgeblendet (opacity: 0, pointer-events: none). Mit .show wird er sichtbar und klickbar.

Dieser Bereich hat data-accordion + .show — er ist sichtbar und klickbar.

Accessibility Referenz

Der Accordion basiert auf nativen <details>/<summary>-Elementen und bringt Barrierefreiheit weitgehend von Haus aus mit. Dennoch müssen Icons, Tastaturnavigation und Screenreader-Ankündigungen korrekt umgesetzt sein.

Natives <details>/<summary>

  • Das <details>-Element hat von Browsers automatisch role="group"
  • Das <summary>-Element hat automatisch role="button" und ist damit per Tastatur fokussierbar
  • Der geöffnete/geschlossene Zustand wird automatisch über aria-expanded vom Browser kommuniziert
  • Es wird kein zusätzliches JavaScript für die grundlegende Funktionalität benötigt

Tastaturnavigation

  • Tab — Fokus auf den nächsten <summary>-Trigger
  • Enter oder Space — Item öffnen oder schließen
  • Im geöffneten Zustand ist der Inhalt per Tab erreichbar, wenn er fokussierbare Elemente enthält
  • Der native Browser-Marker (list-style) wird via CSS entfernt — der Fokusring bleibt erhalten

Icon Handling

  • Alle Icon-Elemente (.accordion-icon-expand, .accordion-icon-collapse) müssen aria-hidden="true" tragen
  • Die Icons sind rein dekorativ — der Zustand wird bereits durch das native <details>-Element kommuniziert
  • Der Icon-Wechsel (expand ↔ collapse) erfolgt via transform: scaleY() und ist für Screenreader irrelevant
  • SVGs sollten keine eigenen role oder aria-label Attribute erhalten

Farbe & Kontrast (WCAG 1.4.3)

  • Der Summary-Text verwendet --fnd-color-text-high — höchster Kontrast gegenüber dem Hintergrund
  • Der Inhaltstext verwendet --fnd-color-text-mid — erfüllt WCAG AA (mindestens 4.5:1) in allen 4 Themes
  • Die Progress Bar verwendet --fnd-color-border-high — der Fortschritt darf nicht ausschließlich durch Farbe kommuniziert werden
  • Icon-Container-Hintergrund: --fnd-color-background-secondary mit --fnd-color-text-mid-Vordergrund

Reduzierte Bewegung (WCAG 2.3.3)

  • Die Icon-Transform-Animation (transition(transform, '200')) wird durch das globale prefers-reduced-motion Mixin automatisch deaktiviert
  • Die Opacity-Animation von [data-accordion] wird ebenfalls durch das globale prefers-reduced-motion abgeschaltet
  • Inhalte sind in beiden Fällen weiterhin vollständig zugänglich
