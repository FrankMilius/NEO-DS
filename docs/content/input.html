Input

Token-basierte Input-Komponente für Text, Email, URL, Tel, Password, Search und Number. Kanonische Klasse: .nc-input (BEM). Alle Werte kommen aus --nc-input-* Component-Tokens.

Accessibility Referenz

Input-Komponenten sind interaktive Formularelemente und müssen die WCAG 2.1 AA-Kriterien erfüllen.

Tastaturnavigation

  • Tab navigiert zum nächsten fokussierbaren Element — Inputs sind nativ fokussierbar
  • Shift + Tab navigiert rückwärts
  • :focus-visible wird automatisch angewendet — sichtbarer Focus-Ring
  • Disabled Inputs (disabled) werden beim Tab-Durchlauf übersprungen
  • Readonly Inputs (readonly) sind fokussierbar, aber nicht editierbar

ARIA-Attribute

  • aria-invalid="true" kennzeichnet eine ungültige Eingabe — Screenreader lesen den Zustand vor
  • aria-describedby verknüpft den Input mit einer Fehlermeldung oder Hilfetext
  • aria-label oder <label> muss für jeden Input vorhanden sein
  • Icons innerhalb des Wrappers sollten aria-hidden="true" tragen, da sie rein dekorativ sind

Fehlerbehandlung

  • Bei Validierungsfehlern immer aria-invalid="true" setzen und .nc-input--error verwenden
  • Die Fehlermeldung muss über aria-describedby mit dem Input verknüpft sein
  • Farbe (roter Rand) darf nicht das einzige Signal für den Fehlerzustand sein (WCAG 1.4.1)
  • Fehlermeldungen sollten als Klartext sichtbar sein, nicht nur über aria-live
  • Beispiel: <span id="err" role="alert">Pflichtfeld</span>

Farbkontrast (WCAG 1.4.3)

  • Input-Text muss mindestens 4.5:1 Kontrast zum Hintergrund haben
  • Placeholder-Text muss mindestens 4.5:1 Kontrast erreichen (oder 3:1 bei Text ≥ 18px)
  • Die Default-Tokens erfüllen WCAG AA — bei Custom-Überschreibungen den Kontrast manuell prüfen
  • Der Focus-Ring muss einen 3:1 Kontrast zum umgebenden Hintergrund haben (WCAG 2.4.7)

Screenreader-Hinweise

  • Jeder Input braucht ein sichtbares <label> oder aria-label
  • Placeholder allein ist kein Ersatz für ein Label (WCAG 3.3.2)
  • Bei dynamischen Fehlern kann aria-live="polite" am Fehlermeldungs-Container sinnvoll sein
  • Screenreader lesen type-Attribut vor — nutze den semantisch korrekten Typ
