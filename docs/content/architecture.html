Architektur des Design Systems

Ueberblick ueber die Schichten des NEO Design Systems: Vom Atomic Design ueber Design Tokens bis zum Recipe-System und SDK.

ITCSS Layer-Architektur

Das NEO Design System verwendet ITCSS (Inverted Triangle CSS) kombiniert mit Atomic Design. Jede Schicht hat eine klare Verantwortung und erhoehte Spezifitaet — von abstrakten Settings bis zu konkreten Utilities.

00
Settings
Design Tokens, Color Maps, Component Tokens — nur Konfiguration, kein CSS-Output
01
Tools
Funktionen (rem(), em()) und Mixins — kein CSS-Output
02
Generic
Reset, Fonts, Keyframe-Animationen — globale Basis-Styles
03
Elements
HTML-Element-Defaults: body, headings, links, Formulare
04
Objects
Layout-Patterns: Container, Grid, Video-Wrapper
05
Atoms
Kleinste Komponenten: Button, Icon, Input, Badge, Chip, Switch
06
Molecules
Kombinationen: Card, Accordion, Breadcrumb, Tabs, Tooltip
07
Organisms
Komplexe Sektionen: Header, Footer, Modal, DataTable, Hero
08
Templates
Seitenlayouts: Shell-Presets (data-layout), .t-dashboard, .t-settings
09
Pages
Seitenspezifische Styles (Docs, Landing)
10
Utilities
Hilfsklassen: .u-sr-only, Sichtbarkeit, Spacing

Entry Point: scss/scss/main.scss — verwendet @use/@forward (moderne Sass-Module). Der Build-Befehl npm run build:css kompiliert alle Layer zu einer einzigen styles.css.

3-Schichten Token-System

Design Tokens bilden die Grundlage fuer konsistentes Styling. Das NEO System verwendet drei aufeinander aufbauende Schichten — von rohen Farbwerten bis zu komponentenspezifischen Variablen.

1. Primitives
--fnd-color-primary-500: #00b259;
--fnd-color-secondary-500: #009fe3;
--fnd-spacing-04: 1rem;
↓
2. Semantic
--fnd-color-interactive-default: var(--fnd-color-primary-500);
--fnd-color-text-primary: var(--fnd-color-neutral-900);
--fnd-color-background-base: var(--fnd-color-always-light);
↓
3. Component
--nc-button-bg: var(--fnd-color-interactive-default);
--nc-button-color: var(--fnd-color-on-accent);
--nc-button-radius: var(--fnd-radius-sm);

Komponenten referenzieren immer ihre eigenen Component-Tokens (var(--nc-button-bg)), nie direkt Primitives oder Semantics. Dadurch koennen einzelne Komponenten per Scope-Override individuell angepasst werden, ohne das Gesamtsystem zu beeinflussen.

Praefixe

PraefixSchichtBeispiel
--fnd-*Foundation (Primitives + Semantic)--fnd-color-primary-500
--nc-*Component--nc-button-bg
--fs-*Fluid Type Scale--fs-lg

Theme-System

Vier Themes werden ueber CSS-Klassen auf dem Root-Element aktiviert. Der Auto-Switch reagiert auf prefers-color-scheme, kann aber per data-theme Attribut ueberschrieben werden.

Theme-KlasseTypBeschreibung
.neo-light-themeNeo Light (Default)Standard-Theme, heller Hintergrund
.neo-dark-themeNeo DarkDunkler Hintergrund, angepasste Kontraste
.customer-light-themeCustomer LightSekundaere Marke, heller Hintergrund
.customer-dark-themeCustomer DarkSekundaere Marke, dunkler Hintergrund

Semantische Token-Maps werden in _color-semantic.scss definiert, die Theme-Klassen und der Auto-Switch in _color-themes.scss. Dark-Mode Component-Overrides befinden sich im Dark-Block von _component-tokens.scss.

Recipe-System v3.1

Jede Komponente hat ein Recipe — eine maschinenlesbare JSON-Datei, die alle Varianten, States, Accessibility-Regeln und Token-Zuweisungen kanonisch beschreibt. Aktuell existieren 89 Recipe-Dateien im System.

Die 9 kanonischen Sektionen

1
meta
Schema-Version, Komponentenname, Status (stable/draft/deprecated), Tags, Links
2
anatomy
Root-Element, benannte Slots, DOM-Hinweise fuer die Implementierung
3
axes
Variationsdimensionen: tone, size, emphasis, pattern — jede Achse ist unabhaengig kombinierbar
4
states
Unterstuetzte States (hover, active, disabled, loading), Prioritaet, Regeln
5
a11y
Accessibility: Kontrast-Ziele, Assertions, bedingte Overrides pro Achsenwert
6
constraints
Business Rules: Zeichenlimits, verbotene Kombinationen, Pflichtfelder
7
styling
Basis-Klassen, Token Groups mit konkreten CSS Custom Properties
8
recipes
Ableitungsregeln: wie Achsen, States und Tokens zu finalen Specs kombiniert werden
9
specimens
Test-Matrizen: vordefinierte Kombinationen fuer visuelle Regression und Dokumentation

Achsen als Variationsdimensionen

Achsen (axes) sind das Kernkonzept des Recipe-Systems. Jede Achse beschreibt eine unabhaengige Variationsdimension einer Komponente. Ein Button hat z.B.:

  • tone — Farb-Semantik: default, success, danger, warning, info
  • size — Groesse: xs, sm, md, lg
  • emphasis — Visuelle Staerke: solid, outline, ghost, link
  • pattern — Inhaltsmuster: standard, with-icon, icon-only

Jeder Achsenwert definiert eine Modifier-Klasse (z.B. .nc-button--success) und optionale Token Groups, die spezifische CSS Custom Properties aktivieren.

Specimens als Test-Matrizen

Specimens definieren vorgefertigte Kombinations-Matrizen, z.B. "Alle Tones × Alle Emphases bei Groesse MD". Das Recipe-SDK expandiert diese Definitionen automatisch zu einzelnen Zellen fuer Rendering und Testing.

Beispiel: Badge Recipe (Auszug)

{
  "meta": { "component": "badge", "schemaVersion": "3.1.0", "status": "stable" },
  "anatomy": { "root": { "element": ".nc-badge" }, "slots": [...] },
  "axes": {
    "tone": {
      "values": {
        "default": { "modifier": null, "tokenGroups": ["tone-default"] },
        "success": { "modifier": "nc-badge--success", "tokenGroups": ["tone-success"] }
      }
    },
    "size": {
      "values": {
        "sm": { "modifier": "nc-badge--sm" },
        "md": { "modifier": null }
      }
    }
  },
  "styling": {
    "baseClasses": ["nc-badge"],
    "tokenGroups": {
      "tone-default": { "tokens": ["nc-badge-default-bg", "nc-badge-default-color"] },
      "tone-success": { "tokens": ["nc-badge-success-bg", "nc-badge-success-color"] }
    }
  },
  "specimens": [
    { "id": "emphasis-grid", "matrix": { "axes": { "tone": "*", "emphasis": "*" } } }
  ]
}

Recipe SDK Pipeline

Das Recipe SDK (packages/recipe-sdk/) ist ein Pure-ESM-Paket, das Recipe-JSON-Dateien laedt, normalisiert und expandiert. Es wird vom Theme Configurator, der CI-Validierung und den Docs verwendet.

1
loadRecipe()
JSON laden, v3.0/v3.1 normalisieren, kanonische Struktur erzeugen
2
expandSpecimenMatrix()
Matrix-Definition → einzelne Zellen mit Achsenwerten expandieren
3
resolveClassList()
Pro Zelle: CSS-Klassen aus baseClasses + Modifier-Klassen ableiten
4
resolveTokenGroups()
Pro Zelle: aktive Token Groups und CSS Custom Properties bestimmen

Consumers

ConsumerSDK-FunktionZweck
Theme ConfiguratorloadRecipe, expandSpecimenMatrixInteraktive Komponenten-Vorschau mit allen Varianten
CI ValidationvalidateRecipe, validateTokenCoverageSchema + semantische Pruefung + Token-Abdeckung
Docs Rezept-TabInline (fetch + render)Automatische Recipe-Dokumentation pro Komponente
