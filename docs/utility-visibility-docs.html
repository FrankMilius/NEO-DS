Utility — Visibility

Utility-Klassen zur Steuerung der Sichtbarkeit von Elementen. Deckt visuelle Ausblendung, vollständiges Verstecken, Fehler-Markierung und Scroll-Sperrung ab. Quelldatei: scss/10-utilities/_visibility.scss.

Visuell versteckt — .visually-hidden

Versteckt ein Element aus dem visuellen Layout, hält es aber im DOM und im Accessibility-Tree. Ähnlich wie .u-sr-only aus der A11y-Utility, jedoch ohne !important-Deklarationen. Geeignet für Inhalte, die visuell nicht angezeigt, aber per Screenreader zugänglich sein sollen.

Sichtbarer Text Dieser Text ist visuell versteckt Weiterer sichtbarer Text 
<span>Sichtbarer Text</span>
<span class="visually-hidden">Nur für Screenreader</span>
<span>Weiterer sichtbarer Text</span>

Vollständig versteckt — .hidden / [hidden]

Setzt display: none !important — das Element wird aus dem visuellen Layout und aus dem Accessibility-Tree entfernt. Entspricht dem nativen HTML hidden-Attribut, das ebenfalls unterstützt wird.

Ich werde versteckt
<!-- CSS-Klasse -->
<div class="hidden">Vollständig unsichtbar</div>

<!-- Natives HTML-Attribut (wird ebenfalls unterstützt) -->
<div hidden>Vollständig unsichtbar</div>

<!-- Via JavaScript ein-/ausblenden -->
element.classList.toggle('hidden');

Block-Fehler — .block-error

Markiert einen Block-Bereich visuell als fehlerhaft mit einem gestrichelten roten Rahmen. Wird typischerweise programmatisch gesetzt, wenn ein Abschnitt oder Widget einen kritischen Fehler hat. Nutzt --fnd-color-semantic-border-danger für den Rahmen.

Dieser Block hat einen Fehler und ist mit gestricheltem Rahmen markiert.

<!-- Block-Fehler-Markierung -->
<section class="block-error">
  Fehlerhafte Sektion
</section>

<!-- Programmatisch setzen -->
element.classList.add('block-error');

Scroll sperren — .scroll-blocked

Sperrt das Scrollen der Seite. Wird auf <body> gesetzt, wenn ein Modal, Drawer oder ein anderes Overlay-Element geöffnet ist. Setzt overflow: hidden und position: fixed; inset: 0. 

<!-- Beim Öffnen eines Modals -->
document.body.classList.add('scroll-blocked');

<!-- Beim Schließen eines Modals -->
document.body.classList.remove('scroll-blocked');

Hinweis: position: fixed kann bei mobilen Browsern dazu führen, dass die Seite an den Anfang springt. Die Scroll-Position vor dem Sperren speichern und nach dem Entsperren wiederherstellen.

Accessibility-Leitfaden

Die Wahl der richtigen Visibility-Klasse hat direkte Auswirkungen auf Screenreader und den Accessibility-Tree.

Richtige Klasse wählen

  • .visually-hidden / .u-sr-only: Wenn Inhalt nur visuell versteckt werden soll (SR liest vor)
  • .hidden / [hidden]: Wenn Inhalt für alle Nutzer versteckt sein soll (auch SR)
  • Niemals visibility: hidden oder opacity: 0 alleine verwenden — diese verstecken visuell, aber nicht im SR
  • display: none und hidden-Attribut entfernen das Element aus dem Accessibility-Tree

.hidden und der Accessibility-Tree (WCAG 4.1.2)

  • Elemente mit .hidden sind für Screenreader nicht zugänglich — auch wenn aria-label gesetzt ist
  • Wenn Inhalte per Toggle ein-/ausgeblendet werden: Fokus korrekt verwalten (Fokus auf das neue sichtbare Element setzen)
  • Für Tabs, Akkordeons und Dialoge: aria-expanded, aria-hidden und aria-controls korrekt aktualisieren
  • Das native hidden-Attribut ist dem CSS gleichwertig; beide Ansätze sind valide

.block-error — Farbe als alleiniges Signal vermeiden (WCAG 1.4.1)

  • Der gestrichelte rote Rahmen allein reicht nicht — zusätzlich eine textuelle Fehlermeldung bereitstellen
  • aria-describedby auf dem fehlerhaften Block auf die Fehlermeldung zeigen lassen
  • Alternativ role="alert" oder aria-live="assertive" für die Fehlermeldung verwenden
  • Fehlermeldungen sollten programmatisch mit dem betroffenen Element verknüpft sein

.scroll-blocked — Fokus-Management bei Overlays (WCAG 2.4.3)

  • Beim Setzen von .scroll-blocked (Modal öffnet): Fokus in das Modal/Overlay verschieben
  • Fokus-Trap innerhalb des Modals implementieren (Tab bleibt innerhalb des Dialogs)
  • Beim Entfernen von .scroll-blocked: Fokus zum auslösenden Element zurückbringen
  • Hintergrundinhalt mit aria-hidden="true" markieren, wenn Modal geöffnet ist

Entscheidungsbaum

Soll der Inhalt für Screenreader zugänglich sein? JA → .visually-hidden oder .u-sr-only NEIN → .hidden oder [hidden]-Attribut Soll der Inhalt bei Fokus/Interaktion sichtbar werden? JA → .visually-hidden (ohne !important, überschreibbar) oder .u-sr-only mit :focus-Ausnahme (z.B. .u-skip-link) NEIN → .hidden (permanent, per JS togglebar) Ist ein Block-Bereich als fehlerhaft zu markieren? → .block-error (+ textuelle Fehlermeldung via aria-describedby) Soll das Scrollen gesperrt werden (Overlay)? → .scroll-blocked auf <body> + Fokus-Management
