NEO Design System

Carousel

Horizontaler Slider mit Fortschrittslinien-Navigation, Vor/Zurück-Buttons und optionalem Autoplay. Kanonische Klasse: .carousel. Alle Farben kommen aus Foundation-Tokens --fnd-*. Slide-Breiten werden per Grid-System (.carousel-slide-width-{1–12}) gesteuert.

Aufbau des Carousels

Das Carousel besteht aus drei Hauptbereichen: dem Slides-Wrapper (.carousel-slides-wrapper) mit der Slide-Liste, der Bottom-Navigation (.carousel-bottom-nav-wrapper) mit Fortschrittslinien und Buttons.

Fortschrittslinien-Zustände

Jede Linie (.carousel-line) hat drei Zustände: inaktiv (schmal, --fnd-color-border-mid), aktiv-statisch (.active, breit, --fnd-color-border-high) und aktiv-autoplay (.active.autoplay, animierte Füllung via @keyframes carousel-line-progress).

Slide-Breiten (Grid-System)

Die Breite jedes Slides wird durch die Klasse .carousel-slide-width-{n} bestimmt, wobei n = 1–12 Rasterspalten entspricht. Die Berechnung erfolgt über die SCSS-Funktion grid-columns($i).

KlasseBreiteTypischer Einsatz
.carousel-slide-width-12100 % (12/12 Spalten)Vollbild-Hero-Slides
.carousel-slide-width-650 % (6/12 Spalten)2 Slides nebeneinander
.carousel-slide-width-433,3 % (4/12 Spalten)3 Slides nebeneinander
.carousel-slide-width-325 % (3/12 Spalten)4 Slides nebeneinander

Accessibility Referenz

Carousels gehören zu den komplexesten interaktiven Komponenten aus Sicht der Barrierefreiheit. Folgende Punkte müssen beachtet werden, um WCAG 2.1 AA zu erfüllen.

ARIA-Rollen und Landmark

  • Der Carousel-Root sollte role="region" und aria-label="Bildkarussell" (oder einen passenden Namen) erhalten
  • Die Slide-Liste (ul) sollte keine eigene ARIA-Rolle benötigen — die semantische Listen-Rolle ist ausreichend
  • Fortschrittslinien sind rein visuell: aria-hidden="true" auf .carousel-line-wrapper
  • Der aktive Slide-Index sollte per aria-live="polite" Region oder aria-label-Update kommuniziert werden

Navigationstasten

  • Alle Buttons müssen aria-label haben: "Vorheriger Slide" und "Nächster Slide"
  • SVG-Icons und .icon-Spans müssen aria-hidden="true" tragen
  • disabled-Attribut beim ersten/letzten Slide korrekt setzen — verhindert unnötige Aktivierung
  • Buttons müssen per Tastatur (Tab, Enter, Space) erreichbar und aktivierbar sein
  • Die Mindestgröße von 32×32px entspricht der WCAG 2.5.5 Zielgröße (AA)

Autoplay (WCAG 2.2.2)

  • Automatisch ablaufende Inhalte, die länger als 5 Sekunden laufen, müssen pausierbar sein
  • Ein Pause-Button oder eine Pause-bei-Hover/Fokus-Logik ist Pflicht bei aktivem Autoplay
  • prefers-reduced-motion sollte das Autoplay und die Slide-Transition deaktivieren
  • Die carousel-line-progress Animation läuft 4 Sekunden — innerhalb der WCAG-5-Sekunden-Grenze
  • Ein Pause-State via Klasse (z.B. .is-paused) sollte die Animation auf animation-play-state: paused setzen

prefers-reduced-motion

  • Die globale Foundation-Regel setzt animation-duration: 0.01ms und transition-duration: 0.01ms bei prefers-reduced-motion: reduce
  • Damit werden Slide-Transition und Fortschrittslinen-Animation automatisch deaktiviert
  • Autoplay sollte zusätzlich via JavaScript bei prefers-reduced-motion: reduce komplett gestoppt werden
