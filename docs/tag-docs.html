Accessibility Referenz

Tag-Komponenten müssen die WCAG 2.1 AA-Kriterien erfüllen. Statische Tags sind dekorativ, interaktive und entfernbare Tags erfordern zusätzliche Semantik.

R5: Statische Tags sind nicht fokussierbar

  • Statische Tags (<span class="nc-tag">) erhalten keinen Fokus
  • Sie dienen nur der visuellen Kategorisierung und sind für Screenreader als normaler Text lesbar
  • Kein tabindex, kein role="button" — reiner Text-Content

R1: Navigation = echtes <a href>

  • Interaktive Tags, die als Links dienen, müssen als <a href="..."> implementiert werden
  • Niemals <span> mit onclick verwenden — das ist nicht barrierefrei
  • Links erhalten automatisch Fokus und können per Enter aktiviert werden

R2: Remove-Aktion = <button> mit aria-label

  • Der Remove-Button muss ein <button>-Element sein
  • Ein beschreibendes aria-label ist Pflicht, z.B. aria-label="Filter A entfernen"
  • Das X-Icon allein ist nicht ausreichend für Screenreader
  • Wird per Enter oder Space aktiviert

R7: Farbe + Text kombiniert (WCAG 1.4.1 / 1.4.3)

  • Farbe allein darf nicht die einzige Informationsquelle sein
  • Jeder Tag enthält beschreibenden Text — die Varianten-Farbe ist rein unterstützend
  • Text muss mindestens 4.5:1 Kontrast zum Hintergrund haben
  • Bei Custom-Farben den Kontrast manuell prüfen

Tastatur-Bedienung

  • Tab: Springt zu interaktiven Tags (<a>) und Remove-Buttons (<button>)
  • Enter: Aktiviert Links (Navigation) und Remove-Buttons (Entfernen)
  • Space: Aktiviert Remove-Buttons (native <button>-Verhalten)
  • Statische Tags sind nicht per Tastatur erreichbar (kein Fokus)
