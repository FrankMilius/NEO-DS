Checkbox

Custom Checkbox mit nativem Input und visuellem Control-Element. Unterstützt Checked, Indeterminate und Disabled. Kanonische Klasse: .nc-checkbox (BEM). Alle Werte kommen aus --nc-checkbox-* Component-Tokens.

DOM-Hinweise

  • Wrapper ist ein <label class='nc-checkbox'> — Klick auf Label aktiviert Input.
  • Native <input type='checkbox'> wird via sr-only versteckt, bleibt aber im DOM fuer Accessibility.
  • __control ist ein <span> — zeigt visuellen Zustand (Border, BG, Checkmark/Minus).
  • :checked → Checkmark SVG via background-image. :indeterminate → Minus-Zeichen.
  • :focus-visible auf dem Native Input delegiert den Focus-Ring auf __control.
  • Error kann per .nc-checkbox--error ODER [aria-invalid='true'] auf dem Input gesetzt werden.
  • Card-Variante (--card): Wrapper bekommt Padding, Border, Radius. Checked-State zeigt aktiven BG + Border.

DOM-Hinweise

  • Flex-Column Container fuer mehrere .nc-checkbox Elemente.
  • Gap via --nc-group-gap. Horizontal: flex-row, flex-wrap, --nc-group-gap-horizontal.
  • Size-Modifier (--sm / --lg) koppelt Gap an Checkbox-Groesse: sm=8px, md=12px (default), lg=16px.
  • Header-Slot: Enthaelt Master-Checkbox (.nc-checkbox) fuer Select-All. Separator via border-bottom.
  • Master-Checkbox nutzt :indeterminate wenn nur Teilmenge ausgewaehlt (JS: input.indeterminate = true).
  • Hint-Slot: Enthaelt .nc-form-hint fuer Gruppen-Hilfetext. Verknuepft via aria-describedby auf dem Gruppen-Container.
  • Error: propagiert border-error auf alle Checkbox-Controls.
  • Disabled: opacity + pointer-events:none auf gesamte Gruppe.

Accessibility Referenz

Native <input type='checkbox'> bleibt im DOM (sr-only). Label via <label> Wrapper oder aria-label. Space-Taste toggled.

Farbkontrast: WCAG AA non-text (3:1)

  • Alle Farbvarianten erfüllen dieses Kontrastziel im Default-Theme.
  • Bei Custom-Überschreibungen den Kontrast manuell prüfen.

Zugänglicher Name erforderlich

  • Komponente muss einen zugänglichen Namen haben (via Text-Inhalt, aria-label oder aria-labelledby).

Wenn: validation = error

  • Pflicht: aria-invalid
  • Pflicht: aria-describedby
  • Error-State braucht aria-invalid='true' auf dem Input und aria-describedby das auf die Fehlermeldung verweist.

Wenn: Spezialbedingung

  • Empfohlen: aria-disabled
  • aria-disabled='true' bevorzugt wenn Checkbox Teil eines sichtbaren Formulars ist.

Wenn: Spezialbedingung

  • Empfohlen: aria-checked-mixed
  • Indeterminate braucht aria-checked='mixed' fuer korrekte Screen-Reader-Ausgabe.

Sub-Komponente: Checkbox Group

Accessibility Referenz

role='group' + aria-labelledby auf Legend/Label. Einzelne Checkboxen haben eigene A11y.

Farbkontrast: WCAG AA normal text (4.5:1)

  • Alle Farbvarianten erfüllen dieses Kontrastziel im Default-Theme.
  • Bei Custom-Überschreibungen den Kontrast manuell prüfen.

Zugänglicher Name erforderlich

  • Komponente muss einen zugänglichen Namen haben (via Text-Inhalt, aria-label oder aria-labelledby).

Wenn: Spezialbedingung

  • Empfohlen: aria-describedby
  • Error: aria-describedby auf Gruppen-Error-Text.

Wenn: Spezialbedingung

  • Empfohlen: aria-checked-mixed
  • Master-Checkbox im Header: Bei Teilauswahl input.indeterminate=true + aria-checked='mixed'. JS muss Zustand synchronisieren: alle gecheckt→checked, keins→unchecked, teilweise→indeterminate.

Wenn: Spezialbedingung

  • Empfohlen: aria-describedby
  • Hint wird via aria-describedby auf dem Gruppen-Container verknuepft (id='hint-{groupname}').
