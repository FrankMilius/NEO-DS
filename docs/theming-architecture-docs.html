NEO Design System

Theming Architecture

Das NEO Design System unterstützt 4 Themes über ein dreischichtiges Token-System, automatische Dark-Mode-Erkennung und markenspezifische Palette-Injektion. Theming ist rein CSS-basiert — kein JavaScript erforderlich.

Die 4 Themes

Das Design System liefert zwei Brand-Varianten (Neo und Customer) mit je einem Light- und Dark-Theme. Die Neo-Themes verwenden die primäre Farbpalette, die Customer-Themes die sekundäre.

Theme CSS-Klasse Color Scheme Brand Auto-Switch
Neo Light .neo-light-theme light NEO (primär) Standard / Default
Neo Dark .neo-dark-theme dark NEO (primär) prefers-color-scheme: dark
Customer Light .customer-light-theme light Customer (sekundär) —
Customer Dark .customer-dark-theme dark Customer (sekundär) —

Theme-Aktivierung

Das aktive Theme wird über das data-theme-Attribut auf dem <html>-Element gesteuert. Ohne explizites Attribut greift der Auto-Switch per @media (prefers-color-scheme: dark).

MethodeBeispielPriorität
Explizit (data-theme) <html data-theme="neo-dark-theme"> Höchste — überschreibt Auto-Switch
CSS-Klasse <html class="customer-light-theme"> Hoch — explizite Klassenanwendung
Auto-Switch (OS) @media (prefers-color-scheme: dark) Standard — greift ohne Attribut

Theme Resolution Flow

Der Auflösungsweg vom data-theme-Attribut bis zum gerenderten Komponentenwert:

01 data-theme Attribut auf <html> oder Auto-Switch per Media Query
02 Theme-Klasse z.B. .neo-dark-theme wird angewendet
03 Token-Auflösung Semantische Tokens erhalten theme-spezifische Werte
04 Rendering Komponenten nutzen aufgelöste Custom Properties

Wichtig: Kein JavaScript nötig

Das Theme-System ist vollständig CSS-basiert. Die Umschaltung zwischen Light und Dark Mode erfolgt über CSS Custom Properties und @media (prefers-color-scheme). JavaScript wird nur für eine optionale manuelle Theme-Umschaltung per UI-Toggle benötigt — das Setzen von data-theme auf <html>.

Drei-Schichten Token-Architektur

Das Theming basiert auf drei Token-Schichten. Jede Schicht referenziert nur die darunter liegende. Nur die semantische Schicht ist theme-aware — sie liefert je nach aktivem Theme unterschiedliche Werte.

Schicht 1: Primitives
--fnd-color-primary-500: #0066cc

Rohe Farbpaletten (primary, secondary, accent, neutral, system). Shade-Skala 100–950. Nicht theme-aware — identische Werte in allen Themes.

↓
Schicht 2: Semantic
--fnd-color-text-primary: var(--fnd-color-neutral-900) ← Light
--fnd-color-text-primary: var(--fnd-color-neutral-100) ← Dark

Rollen-basierte Mappings (text-primary, background-base, interactive-default). Theme-aware — unterschiedliche Werte je nach Light/Dark und Brand.

↓
Schicht 3: Component
--nc-button-bg: var(--fnd-color-interactive-default)

Pro-Komponenten-Tokens. Referenzieren semantische Tokens. Können im Dark-Block von _component-tokens.scss überschrieben werden.

Semantische Maps

In _color-semantic.scss sind 4 Sass-Maps definiert. Jede Map enthält denselben Satz von ~55 semantischen Token-IDs mit unterschiedlichen Palette-Referenzen.

$semantic-dark-base .neo-dark-theme dark NEO (primär)
$semantic-light-secondary .customer-light-theme light Customer (sekundär)
$semantic-dark-secondary .customer-dark-theme dark Customer (sekundär)

Dark-Mode-Strategie

Dark Mode geht über das Invertieren von Farben hinaus. Sechs Strategien stellen sicher, dass Kontrast, Lesbarkeit und visuelle Hierarchie erhalten bleiben.

Surface Elevated
Overlay-Komponenten (Modal, Drawer, Toast, Dropdown) nutzen surface-elevated statt background-base für visuellen Lift auf dunklem Hintergrund.
Feedback-Hintergründe
Dark-spezifische Hintergrundfarben: #0d2b15 (Success), #3b1419 (Danger) — gedämpfte Varianten für dunkle Flächen.
Schatten Auto-Switch
_shadow.scss nutzt @media (prefers-color-scheme: dark) für stärkere, weichere Schatten auf dunklen Flächen.
Hover/Active: always-light
Hover- und Active-States mischen Richtung always-light (nicht always-dark) für sichtbaren Kontrast auf dunklem Hintergrund.
Interaktive Farben
Im Dark Mode wird secondary-500 (#009fe3, Neo Blue) statt primary-500 verwendet — 7.1:1 Kontrast auf Schwarz (WCAG AAA).
Layer-System (Carbon)
--fnd-color-layer-01/02/03 — alternierend in Light, aufsteigend in Dark für verschachtelte Container-Hierarchien.

Komponenten-Token Dark Overrides

Der Dark-Block in _component-tokens.scss überschreibt Komponenten-Tokens für den Dark Mode. Typisches Pattern: 

// _component-tokens.scss — Dark-Block

@media (prefers-color-scheme: dark) {
  .neo-dark-theme,
  :root {
    // Button: aufhellen statt abdunkeln
    --nc-button-bg-hover: color-mix(
      in srgb,
      var(--fnd-color-interactive-default) 85%,
      var(--fnd-color-always-light)
    );

    --nc-button-bg-active: color-mix(
      in srgb,
      var(--fnd-color-interactive-default) 75%,
      var(--fnd-color-always-light)
    );

    // Tag/Chip: transparente Aufhellung
    --nc-tag-bg-hover: color-mix(
      in srgb,
      var(--fnd-color-always-light) 12%,
      transparent
    );
  }
}

color-mix() statt rgba()

Alle transparenten Overlays verwenden color-mix(in srgb, farbe, transparent N%) anstelle von rgba(). Dies ermöglicht die Nutzung von CSS Custom Properties für die Basisfarbe, was mit rgba() nicht möglich ist.

MethodeSyntaxToken-kompatibel?
rgba() (veraltet) rgba(0, 102, 204, 0.15) Nein — erfordert statische RGB-Werte
color-mix() (Standard) color-mix(in srgb, var(--fnd-color-interactive-default) 15%, transparent) Ja — funktioniert mit Custom Properties

Brand-Injektions-Mechanismus

Kundenspezifische Markenfarben werden über Sass-Variablen in _color-primitives.scss injiziert. Aus drei Basisfarben wird automatisch eine vollständige Palette mit Shade-Stufen 100–950 generiert.

Sass-VariableStandardBeschreibung
$brand-source 'neo' Brand-Quelle: 'neo' oder 'customer'
$customer-primary-base null Primärfarbe der Kundenmarke (Hex)
$customer-secondary-base null Sekundärfarbe der Kundenmarke (Hex)
$customer-accent-base null Akzentfarbe der Kundenmarke (Hex)

Integrationsschritte

So wird eine Kundenmarke in das Design System injiziert:

  1. Brand-Quelle setzen
    $brand-source: 'customer'; vor dem Import von _color-primitives.scss definieren.
  2. Basisfarben definieren
    $customer-primary-base: #e63312;
    $customer-secondary-base: #1a7ab5;
    $customer-accent-base: #f5a623;
  3. Palette wird auto-generiert
    Aus jeder Basisfarbe werden die Shade-Stufen 100–950 automatisch per Sass-Farbfunktionen erzeugt (Aufhellung für niedrige Stufen, Abdunklung für hohe).
  4. Customer-Themes verfügbar
    .customer-light-theme und .customer-dark-theme nutzen die sekundären semantischen Maps mit den Customer-Paletten.

Beispiel: Sass-Konfiguration

// custom-brand.scss — Vor dem Haupt-Import

// 1. Brand-Quelle umschalten
$brand-source: 'customer';

// 2. Basisfarben definieren
$customer-primary-base:   #e63312;
$customer-secondary-base: #1a7ab5;
$customer-accent-base:    #f5a623;

// 3. Design System importieren
@use 'scss/scss/main' as *;

// Ergebnis: Alle 4 Themes verfügbar,
// Customer-Themes nutzen die injizierten Paletten.

Paletten-Überblick

Wenn $brand-source: 'customer' gesetzt ist, werden die Paletten nach folgendem Schema aufgebaut:

PaletteQuelle (neo)Quelle (customer)Shade-Stufen

Secondary NEO-Sekundärpalette $customer-secondary-base 100–950
Accent NEO-Akzentpalette $customer-accent-base 100–950
Neutral Immer identisch — nicht markenabhängig 100–950
System Immer identisch — Feedback-Farben (Rot, Grün, Gelb, Blau) 100–950
