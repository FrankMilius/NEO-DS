NEO Design System

Utility — Accessibility

WCAG 2.1-konforme Utility-Klassen für Barrierefreiheit. Diese Klassen stellen sicher, dass Inhalte korrekt für Screenreader, Tastaturnutzer und Nutzer mit motorischen Einschränkungen zugänglich sind. Quelldatei: scss/10-utilities/_a11y.scss.

Screen Reader Only — .u-sr-only

Versteckt Inhalt visuell, hält ihn aber für Screenreader zugänglich. Ersetzt .visually-hidden aus der Visibility-Utility. Wird für zusätzliche Kontextinformationen genutzt, die nur per Screenreader vermittelt werden sollen.

Der “Löschen”-Text ist visuell versteckt, aber im Screenreader lesbar. 
<button aria-label="Dokument löschen">
  <svg aria-hidden="true">...</svg>
  <span class="u-sr-only">Löschen</span>
</button>

ARIA Live Region — .u-live-region

Visuell versteckter Bereich für dynamische Ankündigungen an Screenreader. Kombination mit aria-live="polite" oder aria-live="assertive" und role="status" oder role="alert". 

<div class="u-live-region" aria-live="polite" role="status">
  <!-- JS schreibt hier dynamisch Text rein -->
</div>

<!-- Sofortige Ankündigung (Fehler, Alarm) -->
<div class="u-live-region" aria-live="assertive" role="alert"></div>

Skip Link — .u-skip-link

Überspringt wiederholte Navigation und springt direkt zum Hauptinhalt. Ist standardmäßig offscreen, erscheint aber sichtbar beim Fokus (Tab-Taste). Muss das erste Element im <body> sein. 

<body>
  <a class="u-skip-link" href="#main-content">Zum Hauptinhalt springen</a>
  <header>...Navigation...</header>
  <main id="main-content">...</main>
</body>

Beim Laden der Seite Tab drücken, um den Skip-Link sichtbar werden zu lassen.

Touch Target — .u-touch-target

Stellt sicher, dass interaktive Elemente eine minimale Touch-Fläche von 44×44 px haben (WCAG 2.5.8). Besonders wichtig für kleine Icons, die als Buttons fungieren.

Minimale Touch-Fläche 44×44 px, visuelle Größe kann kleiner sein. 
<button class="u-touch-target" aria-label="Menü öffnen">
  <svg aria-hidden="true">...</svg>
</button>

Focus Ring — .u-focus-ring

Wendet den systemweiten Focus-Ring-Style auf benutzerdefinierte interaktive Elemente an. Ideal für custom-gestylte Elemente, die nicht automatisch den System-Focus-Ring erhalten.

Tab hierher fokussieren
<div class="u-focus-ring" tabindex="0" role="button">
  Custom Interaktives Element
</div>

Reduced Motion — .u-reduced-motion

Deaktiviert alle Transitions und Animationen auf einem Element unabhängig vom System-prefers-reduced-motion-Setting. Ergänzt die globale Media-Query-Unterstützung für programmatische Überschreibung. 

<div class="u-reduced-motion">
  <!-- Keine Transitions oder Animationen -->
</div>

Accessibility-Leitfaden

Diese Utilities sind selbst Accessibility-Werkzeuge. Die folgenden Hinweise beschreiben den korrekten Einsatz.

.u-sr-only — Korrekte Nutzung (WCAG 1.3.1)

  • Verwende .u-sr-only um kontextuellen Text hinzuzufügen, den visuelle Nutzer durch visuellen Kontext verstehen
  • Nicht als Ersatz für aria-label auf interaktiven Elementen — beides kann sinnvoll sein
  • Bei Icon-only-Buttons: .u-sr-only-Text oder aria-label ist Pflicht
  • Niemals wichtige Inhalte dauerhaft per .u-sr-only verstecken — Informationen müssen auch visuell prüfbar bleiben

.u-live-region — Dynamische Ankündigungen (WCAG 4.1.3)

  • aria-live="polite": Ankündigung wartet bis zur nächsten Sprechpause — für Statusmeldungen (Speichern erfolgreich, Daten geladen)
  • aria-live="assertive": Unterbricht sofort — nur für echte Fehler oder zeitkritische Meldungen
  • Live-Regionen müssen beim Seitenaufbau leer sein; erst später Text via JS einfügen
  • Um erneut anzukündigen: Region erst leeren, dann neuen Text setzen (kurzes Timeout)

.u-skip-link — Skip Navigation (WCAG 2.4.1)

  • Muss das erste fokussierbare Element auf der Seite sein
  • href muss auf ein Element mit passender id zeigen (z.B. <main id="main-content">)
  • Mehrere Skip-Links möglich: Hauptinhalt, Suche, Navigation, Footer
  • Das Ziel-Element (<main>) muss tabindex="-1" haben, damit der Fokus korrekt springt (in manchen Browsern)

.u-touch-target — Zielgröße (WCAG 2.5.8)

  • Mindestens 44×44 px Touch-Fläche für alle interaktiven Elemente — wichtig auf mobilen Geräten
  • Die sichtbare Größe darf kleiner sein (z.B. ein 16px-Icon); die Touch-Fläche wird unsichtbar vergrößert
  • Alternative: ausreichend Abstand (Spacing) zwischen kleinen Elementen (WCAG 2.5.8 Ausnahme)
  • Nicht nötig, wenn das Element bereits ≥ 44×44 px ist (z.B. Standard-Buttons)

.u-focus-ring — Sichtbarer Fokus (WCAG 2.4.7 / 2.4.11)

  • Alle interaktiven Elemente müssen einen sichtbaren Fokus-Indikator haben
  • .u-focus-ring verwendet :focus-visible — erscheint nur bei Tastaturnavigation, nicht bei Mausklick
  • Fokus-Ring niemals mit outline: none ohne Ersatz entfernen
  • Für Design-System-Komponenten ist der Fokus-Ring bereits eingebaut; diese Klasse ist für custom Elemente
