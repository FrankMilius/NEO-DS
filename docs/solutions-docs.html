NEO Design System

Solutions

Solutions-Sektion mit Accordion, Side-Content und mobiler Tab-Navigation. Auf Desktop: dreispaltiges Grid (Accordion | Gutter | Side). Auf Mobile: horizontales Scroll-Accordion mit Snap-Verhalten und Tab-Leiste. Kanonische Klasse: .solutions. Wrapper: .solutions-wrapper.

Strukturübersicht

Die Solutions-Komponente ist ein komplexes Desktop/Mobile-adaptives Layout. Auf dem Desktop zeigt ein dreispaltiges Grid den Accordion links und Side-Content rechts. Auf Mobile werden die Accordion-Items horizontal gescrollt, begleitet von einer Tab-Leiste.

Schema: Desktop-Layout

Accordion-Items mit Fortschrittsanzeige

Accordion-Item (Desktop)

Auf dem Desktop zeigt das Accordion eine schmale Titelzeile (h2). Das geöffnete Item hebt den Titel mit primärer Textfarbe hervor. Die Inhalte (.accordion-item-content) sind auf Desktop ausgeblendet, da der Side-Content separat angezeigt wird. Ein Fortschrittsbalken (.accordion-progress) zeigt die aktive Auswahl.

<!-- Accordion-Item Struktur --> <details class="accordion-item" open> <summary class="accordion-item-summary"> <!-- Mobile: Sichtbar --> <!-- Desktop: Summary-Icon ausgeblendet (.accordion-item-summary-icon display:none) --> </summary> <h2>Lösungs-Titel</h2> <p>Kurzbeschreibung (auf Desktop ausgeblendet)</p> <div class="accordion-item-content"> <!-- Auf Desktop nicht sichtbar, nur Mobile --> <p>Detail-Text</p> </div> <div class="accordion-progress"></div> </details>

Labels & Button-Container

Innerhalb der .solutions-Sektion können Label-Gruppen (.labels-container) und Buttons (.button-container) eingesetzt werden, die spezifisches Spacing erhalten.

<div class="labels-container"> <span class="label">Tag 1</span> <span class="label">Tag 2</span> </div> <div class="button-container"> <button class="button button--primary">Mehr erfahren</button> </div>

Accessibility Referenz

Die Solutions-Komponente ist eine der komplexesten Strukturen im System. Besondere Aufmerksamkeit gilt der synchronisierten Tab/Accordion-Navigation und dem horizontalen Scroll-Verhalten auf Mobile.

Native <details>/<summary> für das Accordion

  • Die Verwendung nativer <details>/<summary>-Elemente gewährleistet Screenreader-Kompatibilität ohne zusätzliche ARIA
  • Der geöffnete/geschlossene Zustand wird automatisch angekündigt
  • Die <summary> muss einen aussagekräftigen Text enthalten
  • Das h2-Element innerhalb des Items sollte hierarchisch korrekt sein

Horizontales Scrollen (Mobile)

  • Der horizontale Scroll-Bereich (.accordion--solutions) sollte tabindex="0" erhalten, damit Tastaturnutzer scrollen können
  • scroll-snap-type: x mandatory sorgt für sauberes Scrollen, muss aber bei prefers-reduced-motion beachtet werden
  • Die Mobile Tab-Leiste dient als sichtbares Navigationsmittel und sollte mit dem Accordion-Status synchronisiert sein

Mobile Tab-Leiste

  • Die Mobile Tab-Leiste ist visuell als Navigation implementiert, sollte aber mit korrekten ARIA-Rollen ausgezeichnet werden
  • Aktive Tabs sollten aria-selected="true" bzw. aria-current="true" erhalten
  • Die <ul>-Liste sollte in einem <nav> oder mit role="tablist" und aria-label umgeben werden
  • Tab-Klicks müssen den entsprechenden Accordion-Eintrag sichtbar scrollen

Grid-Reihenfolge und DOM-Reihenfolge

  • Die CSS Grid-Areas verlagern das Side-Panel visuell nach rechts, obwohl es DOM-first erscheint
  • Screenreader folgen der DOM-Reihenfolge — stellen Sie sicher, dass die Lese-Reihenfolge logisch ist
  • Das erste Kind wird visuell als Side-Area (rechts) gezeigt, DOM-logisch steht es aber vor dem Accordion
  • Prüfen Sie die Tab-Reihenfolge mit einem Screenreader auf Sinnhaftigkeit
