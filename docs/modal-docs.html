NEO Design System

Modal

Drei spezialisierte Modal-Varianten auf Basis des nativen <dialog>-Elements: .location-preference-modal (Slide-in Panel rechts), .contextual-notification-modal (Toast-ähnliches Slide-up unten) und .theme-switcher-modal (Slide-in Panel rechts mit Theme-Auswahl). Alle Varianten nutzen @starting-style für CSS-native Ein-/Ausblend-Animationen und Body-Scroll-Lock via body:has([open]).

JavaScript API

Alle Modals nutzen die native <dialog>-API. Das Öffnen und Schließen erfolgt ausschließlich über showModal() und close().

// Öffnen (modal — mit Backdrop, Focus-Trap, aria-modal) const modal = document.querySelector('.location-preference-modal'); modal.showModal(); // Schließen modal.close(); // Schließen über Close-Button document.querySelector('.close-btn').addEventListener('click', () => { modal.close(); }); // Event: Modal wurde geschlossen modal.addEventListener('close', () => { console.log('Modal geschlossen'); }); // Backdrop-Click schließt (contextual-notification-modal — kein Backdrop auf Mobile) // location-preference-modal und theme-switcher-modal haben Backdrop ab Desktop modal.addEventListener('click', (e) => { if (e.target === modal) modal.close(); });

Accessibility Referenz

Alle Modal-Varianten basieren auf dem nativen <dialog>-Element und erfüllen WCAG 2.1 AA. Fokus-Trap, ESC-Close und aria-modal sind nativ in showModal() integriert.

Natives <dialog>

  • Automatisch role="dialog" und aria-modal="true" bei showModal()
  • Kein manuelles ARIA-Setup nötig — der Browser übernimmt die korrekte Semantik
  • Unterstützt in allen modernen Browsern (Chrome, Firefox, Safari, Edge)
  • Jede Variante muss zwingend aria-labelledby mit der Titel-ID verknüpfen

aria-labelledby

  • .location-preference-modal: aria-labelledby verlinkt auf .dialog-header
  • .contextual-notification-modal: aria-labelledby verlinkt auf h2 in .notification-heading
  • .theme-switcher-modal: aria-labelledby verlinkt auf .theme-switcher__title
  • Screenreader lesen beim Öffnen automatisch den Titel vor

Focus-Trap

  • Nativ bei showModal() — Fokus bleibt im Dialog
  • Tab-Navigation zykliert zwischen den interaktiven Elementen innerhalb des Modals
  • Elemente außerhalb des Dialogs sind nicht erreichbar (inert)
  • Kein JavaScript-basierter Focus-Trap nötig

Close-Button

  • Alle Varianten haben einen .close-btn bzw. .theme-switcher__close
  • Buttons verwenden all: unset — aria-label="Schließen" ist zwingend erforderlich, da kein sichtbarer Text vorhanden ist
  • Alle Close-Buttons haben :focus-visible mit @include focus-ring

ESC-Close

  • Native Tastaturunterstützung — ESC schließt das Modal
  • Löst das cancel-Event aus, gefolgt vom close-Event
  • Optional: e.preventDefault() im cancel-Event blockiert das Schließen per ESC (z.B. bei ungespeicherten Änderungen)

Focus-Rückkehr

  • Fokus kehrt automatisch zum Trigger-Element zurück, das das Modal geöffnet hat
  • Natives Verhalten von <dialog> — kein manuelles Focus-Management nötig
  • Funktioniert sowohl bei close() als auch bei ESC
  • Für .theme-switcher-fab: Fokus kehrt nach Schließen automatisch zum FAB zurück

Body-Scroll-Lock

  • CSS-basiert via body:has(.location-preference-modal[open]) { overflow: hidden; }
  • Gilt ebenso für .theme-switcher-modal
  • .contextual-notification-modal hat keinen Scroll-Lock — es ist ein nicht-modales Toast-ähnliches Element
  • Verhindert Hintergrund-Scrollen, solange ein Vollbild- oder Panel-Modal offen ist
  • Kein JavaScript nötig — rein deklarativ

Theme Switcher FAB

  • aria-label="Theme wechseln" erforderlich (kein sichtbarer Text)
  • aria-haspopup="dialog" signalisiert Screenreadern, dass ein Dialog geöffnet wird
  • aria-controls kann optional auf die Dialog-ID verweisen
  • Theme-Kacheln (.theme-switcher__option) sind <button>-Elemente mit lesbarem .theme-switcher__option-label
  • Aktive Kachel sollte aria-pressed="true" erhalten, um den aktiven Zustand für Screenreader anzuzeigen

Reduced Motion

  • Das globale prefers-reduced-motion-Media-Query in _animations.scss deaktiviert alle transition- und animation-Eigenschaften systemweit
  • Bei aktiviertem Reduced Motion erscheinen alle Modals ohne Slide- oder Fade-Animation
  • Die @starting-style-Eintrittsanimationen werden ebenfalls unterdrückt
