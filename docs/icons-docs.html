NEO Design System

Icons

Token-basierte Icon-Library mit 6 Größenstufen, semantischen Farben, Touch-Target-Support und Button-Icon-Mapping. Alle Werte kommen aus --nc-icon-* Component-Tokens.

Icon-Größen

6 Stufen von xs (16px) bis 2xl (36px). Der Default ist sm (20px), optimiert für Inline-Nutzung neben Body-Text.

Richtlinien

Stil
Alle Icons sind solid und monochrom. Sie verwenden currentColor, damit sie sich automatisch an das aktuelle Theme anpassen.
Kontrast
Icons folgen denselben Kontrast-Anforderungen wie Typografie: WCAG AA 4.5:1 gegen den Hintergrund. Die semantischen Farb-Tokens garantieren dies automatisch.
Touch Targets
Interaktive Icons benötigen eine Mindest-Touch-Target-Größe von 44×44px. Nutze .icon--interactive oder füge Padding hinzu.
Ausrichtung
Icons neben Text werden vertikal zentriert ausgerichtet. Nutze inline-flex + align-items: center auf dem Container.

Icon Accessibility

Icons können dekorativ oder informativ sein. Die korrekte Auszeichnung entscheidet darüber, ob ein Screen Reader das Icon liest oder ignoriert.

Entscheidungsbaum

KontextTypAktion
Icon neben sichtbarem Text (z.B. Button mit Label) Dekorativ aria-hidden="true" auf das Icon
Icon als alleiniger Inhalt (z.B. Icon-only Button) Informativ aria-label auf den <button>
Icon transportiert eigenständige Bedeutung (z.B. Status-Icon) Informativ role="img" + aria-label auf das Icon
Icon ist rein ästhetisch (Hintergrund-Schmuck) Dekorativ aria-hidden="true" auf das Icon

Dekorative Icons

Dekorative Icons bieten keinen zusätzlichen Informationsgehalt. Sie werden vor Screen Readern versteckt, damit sie die Sprachausgabe nicht stören.

Do: aria-hidden="true" auf das Icon setzen 
<!-- Icon neben Text: dekorativ -->
<button class="nc-button nc-button--primary">
  <span class="nc-button__icon" aria-hidden="true">
    <svg>…</svg>
  </span>
  <span class="nc-button__label">Speichern</span>
</button>

Warum? Der Button-Text „Speichern“ vermittelt die Bedeutung. Das Icon wiederholt nur visuell — es würde im Screen Reader zu „Diskette Speichern“ führen (redundant).

Informative Icons

Wenn ein Icon die einzige Information trägt, muss es einen zugaenglichen Namen erhalten.

Icon-only Button

Do: aria-label auf den Button (nicht auf das SVG) 
<button class="icon icon--md icon--interactive" aria-label="Menü öffnen">
  <svg aria-hidden="true">…</svg>
</button>
Don't: Button ohne aria-label — Screen Reader liest „Button“ ohne Kontext 
<!-- FALSCH: kein zugaenglicher Name -->
<button class="icon icon--md icon--interactive">
  <svg>…</svg>
</button>

Standalone Status-Icon

<!-- Status-Icon mit Bedeutung -->
<span class="icon icon--sm" role="img" aria-label="Erfolg">
  <svg>…</svg>
</span>

Farbe ist nie alleiniges Signal (WCAG 1.4.1)

Icons dürfen Farbe als zusätzliches Signal nutzen, aber nie als einziges. Kombiniere Farbe immer mit Text, Form oder Position.

Do: Grünes Checkmark-Icon + Text „Erfolgreich“
Don't: Nur ein rotes/grünes Icon ohne Kontext

Kontrast (WCAG 1.4.11)

Icons, die Information transportieren, müssen ein Kontrastverhältnis von mindestens 3:1 zum Hintergrund haben (Non-Text Contrast). Die semantischen Farb-Tokens (--nc-icon-color-*) erfüllen dies automatisch auf allen vier Theme-Varianten.

Farb-TokenKontrast-Verhältnis (Light)Kontrast-Verhältnis (Dark)
--nc-icon-color-default≥ 12:1≥ 12:1
--nc-icon-color-secondary≥ 4.5:1≥ 4.5:1
--nc-icon-color-tertiary≥ 3:1≥ 3:1
--nc-icon-color-disabled< 3:1 (beabsichtigt)< 3:1 (beabsichtigt)

Hinweis: Deaktivierte Icons (.icon--disabled) fallen bewusst unter die Kontrastgrenze — WCAG 1.4.3 nimmt deaktivierte Elemente explizit aus.

Touch Targets (WCAG 2.5.5 / 2.5.8)

Interaktive Icons müssen eine Mindest-Touch-Target-Größe von 44×44px haben (Level AAA: 44px, Level AA: 24px mit Spacing).

MethodeWannBeispiel
.icon--interactive Standalone klickbares Icon Close-Button, Menu-Toggle
Button mit Padding Icon in einer Button-Komponente .nc-button--icon-only
min-width / min-height Custom Interactive-Wrapper Eigener Wrapper mit 44px Mindestgröße

Focus Indicator (WCAG 2.4.7 / 2.4.11)

Alle interaktiven Icons brauchen einen sichtbaren Focus-Ring. Die Klasse .icon--interactive nutzt :focus-visible mit den Foundation-Tokens: 

/* Automatisch via .icon--interactive */
:focus-visible {
  outline: var(--fnd-focus-ring-width) solid var(--fnd-color-interactive-focus);
  outline-offset: var(--fnd-focus-ring-offset);
}

Der Focus-Ring erscheint nur bei Tastatur-Navigation (:focus-visible), nicht bei Mausklick. Das ist WCAG-konform und vermeidet visuelle Störung.

Reduced Motion (WCAG 2.3.3)

Animierte Icons (z.B. Spinner) respektieren prefers-reduced-motion. Die Foundation stellt dies über globale Keyframe-Deklarationen sicher: 

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
