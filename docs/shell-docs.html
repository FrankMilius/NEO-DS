NEO Design System

Shell & Scaffolding

Universelles Layout-System mit Linkbar, Navigation, konfigurierbaren Sidebars, Content-Bereich und Footerbar. Aktiviert via data-layout-Attribut auf <body>. Alle Werte kommen aus --nc-shell-* Component-Tokens.

Architektur

Die Shell definiert ein CSS Grid mit Named Areas fuer die aeussere Seitenstruktur. Layout-Varianten werden ueber data-layout-Presets auf <body> gesteuert. Kein JavaScript fuer die Grundfunktion noetig.

Content-Alignment

Der .nc-shell__content-body unterstuetzt drei Ausrichtungsmodi:

ModifierVerhaltenMax-Width
--left Linksbuendig, begrenzte Breite var(--nc-shell-content-max-width) (1200px)
--center Zentriert, begrenzte Breite var(--nc-shell-content-max-width) (1200px)
(default / --full) Volle verfuegbare Breite keine Begrenzung

RTL-Unterstuetzung

Alle Positionierungen verwenden CSS Logical Properties (inset-inline-start, margin-inline, border-inline-end). Bei dir="rtl" auf <html> spiegelt das Layout automatisch — kein zusaetzlicher Code noetig.

Layout-Presets

Presets werden via data-layout="..." auf <body> aktiviert. Jedes Preset steuert Sichtbarkeit und Dimensionen der Shell-Zonen.

Preset Linkbar Sidebar L Sidebar R Footerbar Content
dashboard hidden 260px hidden visible full
content-page hidden hidden hidden visible center (1200px)
docs hidden 240px 200px visible left
landing visible (32px) hidden hidden visible full
focused hidden hidden hidden hidden center (720px)
settings hidden 220px hidden visible left (960px)

Preset: Dashboard

Linke Sidebar (260px) fuer Navigation zwischen Dashboard-Bereichen. Content ueber volle Breite. Footerbar fuer Status-Info. Kein Linkbar.

<body data-layout="dashboard">

Zentrierter Content (max 1200px), keine Sidebars. Ideal fuer Artikel, Blog-Posts und redaktionelle Inhalte.

Minimales Layout: kein Linkbar, keine Sidebars, kein Footerbar. Content auf 720px zentriert. Fuer Formulare, Login, Error-Seiten.

JSON-Konfiguration

Linkbar und Footerbar werden ueber JSON-Dateien im data/-Verzeichnis konfiguriert. Die JSON-Dateien werden in Phase 2 (Sidebar-Toggle + JS) per fetch() geladen und in die Shell gerendert.

shell-linkbar.json

Konfiguriert die Linkbar-Inhalte (Links und Icon-Links).

JSON 
{
  "$meta": {
    "description": "Shell Linkbar-Konfiguration",
    "version": "1.0.0"
  },
  "items": [
    {
      "id": "placeholder-link",
      "type": "link",
      "label": "Placeholder Link",
      "href": "#",
      "position": "left"
    },
    {
      "id": "placeholder-icon",
      "type": "icon-link",
      "icon": "brand-linkedin",
      "href": "#",
      "label": "LinkedIn",
      "target": "_blank",
      "position": "right"
    }
  ]
}

shell-footerbar.json

Konfiguriert die Footerbar mit 3 Zonen (left, center, right).

JSON 
{
  "$meta": {
    "description": "Shell Footerbar-Konfiguration",
    "version": "1.0.0"
  },
  "zones": {
    "left":   [{ "id": "build-version", "type": "text", "template": "Build: {{version}}" }],
    "center": [],
    "right":  [{ "id": "last-changed", "type": "text", "template": "Letzte Aenderung: {{date}}" }]
  }
}

JavaScript API

js/shell.js steuert Sidebar-Toggle, Off-Canvas-Drawer und JSON-Rendering.

Initialisierung

JS 
// Einzelne Shell initialisieren
const shell = setupShell(document.querySelector('.nc-shell'));

// Alle Shells auf der Seite
setupShells();

// Mit Optionen (JSON-Pfade ueberschreiben)
const shell = setupShell(el, {
  linkbarUrl: '/api/linkbar.json',
  footerbarUrl: '/api/footerbar.json'
});

API-Methoden

MethodeBeschreibung
toggleSidebar(side) Sidebar umschalten. side: 'left' oder 'right'. Desktop: Collapse/Expand. Mobile: Off-Canvas-Drawer.
openDrawer(side) Off-Canvas-Drawer oeffnen (Mobile). Schliesst ggf. den anderen Drawer.
closeDrawer(side) Off-Canvas-Drawer schliessen. Focus zurueck auf Toggle-Button.
closeAllDrawers() Alle offenen Drawer schliessen.
destroy() Alle Event-Listener entfernen, Overlay entfernen, Body-Scroll freigeben.

Toggle-Buttons

Toggle-Buttons werden ueber das data-shell-toggle-Attribut im Navbar platziert. Die Icons wechseln automatisch zwischen Collapse und Expand.

HTML 
<!-- Im Navbar -->
<button data-shell-toggle="sidebar-left" type="button">
  <!-- Icon wird automatisch injiziert -->
</button>

<button data-shell-toggle="sidebar-right" type="button">
  <!-- Icon wird automatisch injiziert -->
</button>

Off-Canvas (Mobile)

Unter dem lg-Breakpoint (1024px) oeffnen Sidebars als Off-Canvas-Drawer mit Overlay. Per data-sidebar-mobile-Attribut kann das Verhalten pro Sidebar konfiguriert werden:

WertVerhalten
drawer (Default) Sidebar faehrt als Drawer von der Seite herein. Overlay-Backdrop, ESC schliesst.
hidden Sidebar wird auf Mobile komplett ausgeblendet (kein Drawer).
HTML 
<aside class="nc-shell__sidebar-left" data-sidebar-mobile="drawer">
  ...
</aside>

<aside class="nc-shell__sidebar-right" data-sidebar-mobile="hidden">
  ...
</aside>

Data-Attribute

AttributElementBeschreibung
data-shell-toggle Button "sidebar-left" oder "sidebar-right" — Toggle-Button fuer Sidebar
data-sidebar-mobile Sidebar "drawer" (Default) oder "hidden" — Mobiles Verhalten
data-shell-linkbar .nc-shell URL zur Linkbar-JSON-Datei (Default: data/shell-linkbar.json)
data-shell-footerbar .nc-shell URL zur Footerbar-JSON-Datei (Default: data/shell-footerbar.json)

CSS-Klassen (durch JS gesetzt)

KlasseBeschreibung
.nc-shell--sidebar-left-collapsed Linke Sidebar eingeklappt (Desktop)
.nc-shell--sidebar-right-collapsed Rechte Sidebar eingeklappt (Desktop)
.nc-shell--sidebar-left-drawer-open Linker Off-Canvas-Drawer geoeffnet (Mobile)
.nc-shell--sidebar-right-drawer-open Rechter Off-Canvas-Drawer geoeffnet (Mobile)

Template-Migration

Die bisherigen .t-* Templates werden schrittweise durch das Shell-System mit data-layout-Presets ersetzt. Die alten Template-Dateien bleiben erhalten, bis die HTML-Migration vollstaendig abgeschlossen ist.

Mapping: Alt → Neu

Alte Klasse Shell-Preset SCSS-Datei Aufwand
.t-dashboard data-layout="dashboard" _dashboard.scss Mittel
.t-content data-layout="content-page" _content-page.scss Niedrig
.t-settings data-layout="settings" _settings-page.scss Niedrig
.t-form-page data-layout="focused" _form-page.scss Niedrig
.t-error data-layout="focused" _error-page.scss Niedrig
.home-hero data-layout="landing" _home-hero.scss Hoch
.home-basic data-layout="landing" _home-basic.scss Mittel
.docs-layout data-layout="docs" 09-pages/_docs.scss Hoch

Migrationsanleitung

Fuer jedes Template sind drei Schritte noetig:

  1. Aeusseres Layout ersetzen: data-layout="..." auf <body> setzen und .nc-shell Markup verwenden.
  2. Content in Shell-Zonen einsetzen: Inhalte in .nc-shell__main / .nc-shell__sidebar-left etc. verschieben.
  3. Component-Styles behalten: Innere Klassen wie .t-dashboard__metric-card oder .t-error__code bleiben unveraendert.

Beispiel: .t-settings → data-layout="settings"

Vorher (alt) 
<body>
  <header class="nc-header">...</header>
  <div class="t-settings">
    <nav class="t-settings__nav">...</nav>
    <div class="t-settings__content">...</div>
  </div>
</body>
Nachher (neu) 
<body data-layout="settings">
  <div class="nc-shell">
    <header class="nc-shell__navbar">
      <!-- nc-header Inhalte -->
    </header>
    <div class="nc-shell__stage">
      <aside class="nc-shell__sidebar-left">
        <nav class="t-settings__nav">...</nav>
      </aside>
      <main class="nc-shell__main">
        <div class="nc-shell__content-body">
          <div class="t-settings__content">...</div>
        </div>
      </main>
    </div>
    <footer class="nc-shell__footerbar">
      <div class="nc-shell__footerbar-left"></div>
      <div class="nc-shell__footerbar-center"></div>
      <div class="nc-shell__footerbar-right"></div>
    </footer>
  </div>
  <script src="js/shell.js"></script>
  <script>setupShells();</script>
</body>

Was bleibt erhalten

Die Shell uebernimmt nur die aeussere Seitenstruktur (Grid, Sidebars, Sticky-Verhalten). Alle inneren Component-Styles der Templates bleiben unveraendert:

TemplateErhaltene Styles
.t-dashboard __sidebar-link, __metric-card, __card, __card-header
.t-content __body (Prose-Styles), __toc, __toc-link, __meta
.t-settings __nav-link, __section, __row, __row-label
.t-form-page __section, __row, __actions
.t-error __code, __title, __description, __actions
.home-hero Komplett (Char-Animation, World-Globe, Highlights)
.home-basic -title, -media, -body, -link

Was entfaellt

Nach der Migration koennen folgende Layout-Selektoren aus den alten Templates entfernt werden:

TemplateEntfallende SelektorenErsetzt durch
.t-dashboard Root-Grid, __sidebar (Layout), __header (Grid-Area) Shell-Grid + .nc-shell__sidebar-left
.t-content Root-Grid (max-width, grid-template-columns) Shell content-page Preset
.t-settings Root-Grid (grid-template-columns: 220px 1fr) Shell settings Preset
.t-form-page max-width: 720px; margin-inline: auto Shell focused Preset (--nc-shell-content-narrow)
.t-error display: grid; place-items: center; min-height Shell focused Preset
.docs-layout Root-Grid, Sidebar-Columns, max-width: 1600px Shell docs Preset + _template.html

Content Templates

Wiederverwendbare Inhalts-Layouts fuer den .nc-shell__content-body. Jedes Template definiert ein spezifisches Grid/Flow-Pattern fuer gaengige Seitentypen. Kombinierbar mit allen Shell-Presets.

BEM-Praefix: .t-{name} (ct = Content Template)

Uebersicht

TemplateVerwendungLayout-Typ
.t-dashboard-overview Dashboard-Startseiten mit KPI-Karten und Detail-Cards Flex + auto-fit Grid
.t-article Blog-Posts, Artikel, Dokumentationsseiten Prose + optionale TOC-Sidebar
.t-card-grid Produkt-Uebersichten, Galerie-Seiten, Feature-Listen auto-fill Grid (responsive)
.t-form Registrierung, Login, Kontaktformular, Checkout Zentriert, max 720px
.t-split Feature-Beschreibungen, Media + Text, Split-Screens 2-Spalten (50/50 oder 60/40)

  <div class="nc-shell">

    <main class="nc-shell__main">

        <div class="t-dashboard-overview">
          <div class="t-dashboard-overview__metrics">...</div>
          <div class="t-dashboard-overview__cards">...</div>
        </div>
      </div>
    </main>
  </div>
</body>
