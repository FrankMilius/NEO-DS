NEO Design System

Recipe System

Das Recipe v3.1 System beschreibt jede Komponente als strukturierte JSON-Datei. Recipes definieren Variationen (Achsen), Zustände, Accessibility-Verträge, Token-Wiring und Test-Specimens. Sie werden vom Theme Configurator konsumiert und durch lint-recipes.mjs validiert. Schema: data/recipe-schema.json.

Was ist ein Recipe?

Ein Recipe ist eine strukturierte JSON-Datei, die eine Komponente vollständig beschreibt: ihre Variationen, interaktiven Zustände, Accessibility-Anforderungen, Token-Zuordnungen und Test-Specimens. Jede Komponente im NEO Design System hat genau ein Recipe.

Schema-Version: 3.1.0 — Das JSON Schema liegt unter data/recipe-schema.json und wird von scripts/lint-recipes.mjs zur Validierung herangezogen. Aktuell existieren 92 Recipe-Dateien im data/ Verzeichnis.

Die 9 kanonischen Sektionen

Jedes Recipe besteht aus bis zu 9 Sektionen. Nur meta ist zwingend erforderlich — alle anderen Sektionen sind optional, aber empfohlen für den Status stable.

Sektion Zweck Wichtige Felder
meta Identität & Metadaten schemaVersion, component, version, status, tags, links
anatomy DOM-Struktur root.element, slots[], domNotes[]
axes Variations-Dimensionen Pro Achse: label, values — jeder Wert hat modifier, tokenGroups
states Interaktive Zustände supported[], precedence[], interactive, rules[]
a11y Accessibility-Vertrag role, aria-*, keyboard, assertions[]
styling Token-Wiring baseClasses[], baseTokenGroups[], tokenGroups{}
recipes Klassen-Auflösung mode (static/dynamic), resolution.template
specimens Test-Matrizen id, label, matrix.axes, matrix.states, layout
links Querverweise docs, figma, storybook

Namenskonventionen

Recipe-Dateien folgen einem strikten Benennungsschema:

EigenschaftKonventionBeispiel
Dateiname {component}-recipe.json button-recipe.json, data-table-recipe.json
Component-ID Lowercase Kebab-Case button, segmented-control
Achsen-Schluessel Lowercase camelCase variant, size, intent
Modifier Lowercase Kebab-Case oder null "filled", "outline", null (= Default)

Status-Werte

Jedes Recipe trägt einen meta.status der den Reifegrad anzeigt:

StatusBedeutungErlaubte Änderungen
draft Entwurf — unvollständig, nicht für Produktion Beliebige Änderungen, Breaking Changes erlaubt
experimental Experimentell — Grundstruktur steht, API kann sich ändern API-Änderungen mit Deprecation-Hinweis
stable Stabil — produktionsreif, alle 9 Sektionen vorhanden Nur additive Änderungen, keine Breaking Changes
deprecated Veraltet — wird in zukünftiger Version entfernt Nur Bug-Fixes, meta.deprecatedBy gesetzt

Minimales Recipe-Beispiel

Die einfachste gültige Recipe-Datei enthält nur die meta-Sektion: 

{
  "meta": {
    "schemaVersion": "3.1.0",
    "component": "divider",
    "version": "1.0.0",
    "status": "stable",
    "tags": ["layout", "atom"]
  }
}

Was sind Achsen?

Achsen (Axes) sind benannte Variations-Dimensionen einer Komponente. Typische Achsen sind variant (filled, outline, ghost), size (sm, md, lg) und intent (default, success, danger). Jede Achse definiert eine endliche Menge von Werten, die kombiniert den gesamten Variationsraum der Komponente aufspannen.

Achsen-Wert-Struktur

Jeder Achsen-Wert definiert einen modifier (CSS-Klasse) und eine Liste von tokenGroups (Styling-Verbindung): 

{
  "axes": {
    "variant": {
      "label": "Variante",
      "values": {
        "filled": {
          "modifier": "filled",
          "tokenGroups": ["filled"]
        },
        "outline": {
          "modifier": "outline",
          "tokenGroups": ["outline"]
        },
        "ghost": {
          "modifier": null,
          "tokenGroups": ["ghost"]
        }
      }
    }
  }
}

Modifier-Regeln

modifier-WertBedeutungResultierende CSS-Klasse
null Default-Variante — keine zusätzliche Klasse erforderlich .nc-{component} (nur Basis-Klasse)
"filled" Benannte Variante — Modifier-Klasse wird angehängt .nc-{component}--filled
"outline" Benannte Variante .nc-{component}--outline
Konvention: modifier: null kennzeichnet den Default-Zustand. Wenn eine Komponente ohne Modifier-Klasse gerendert wird, gilt dieser Achsen-Wert. Pro Achse darf maximal ein Wert null als Modifier haben.

Token Groups

Jeder Achsen-Wert verweist über tokenGroups auf benannte Gruppen in styling.tokenGroups. Dadurch wird die Verbindung zwischen Variationen und konkreten Design-Tokens hergestellt.

axes.variant.filled → tokenGroups: ["filled"] → styling.tokenGroups.filled → --nc-button-bg, --nc-button-color

Specimens: Test-Matrizen

Specimens sind vordefinierte Test-Matrizen, die Achsen und Zustände kombinieren. Der Theme Configurator rendert Specimens als visuelle Prüftafeln.

LayoutBeschreibungKonfiguration
row Horizontale Auflistung aller Achsen-Werte —
grid Zweidimensionale Matrix (Zeilen × Spalten) layoutConfig.rowAxis, layoutConfig.colAxis
single Einzelnes Exemplar mit festgelegten Werten —

Specimen-Beispiel

Ein Grid-Specimen, das alle Varianten × Größen in Default- und Hover-Zustand zeigt: 

{
  "id": "variant-matrix",
  "label": "Varianten-Matrix",
  "matrix": {
    "axes": {
      "variant": "*",
      "size": "*"
    },
    "states": ["default", "hover"]
  },
  "layout": "grid",
  "layoutConfig": {
    "rowAxis": "variant",
    "colAxis": "size"
  }
}
Wildcard "*": Bedeutet “alle Werte dieser Achse”. Alternativ kann ein Array mit spezifischen Werten angegeben werden: "variant": ["filled", "outline"].

Basis-Styling

Das styling-Objekt definiert, welche CSS-Klassen und Token-Gruppen den Grundzustand einer Komponente bilden:

FeldTypBeschreibung
baseClasses string[] CSS-Klassen, die immer gesetzt werden (z.B. ["nc-button"])
baseTokenGroups string[] Token-Gruppen, die immer aktiv sind (z.B. ["base", "layout"])
tokenGroups object Benannte Token-Gruppen, referenziert von Achsen-Werten 
{
  "styling": {
    "baseClasses": ["nc-button"],
    "baseTokenGroups": ["base", "layout"],
    "tokenGroups": {
      "base": {
        "label": "Basis",
        "tokens": ["nc-button-radius", "nc-button-font-weight"]
      },
      "filled": {
        "label": "Filled",
        "tokens": ["nc-button-bg", "nc-button-color", "nc-button-border"]
      },
      "outline": {
        "label": "Outline",
        "tokens": ["nc-button-bg", "nc-button-color", "nc-button-border"]
      }
    }
  }
}

Token-Gruppen-Struktur

Jede Token-Gruppe ist ein Objekt mit label (Anzeigename) und tokens (Array von Token-Namen ohne -- Prefix):

FeldTypBeschreibung
label string Menschenlesbarer Name der Gruppe (wird im Theme Configurator angezeigt)
tokens string[] Token-Namen, z.B. "nc-button-bg" → CSS: var(--nc-button-bg)

Theme Configurator Integration

Der Theme Configurator liest die tokenGroups eines Recipes und baut daraus sein Inspector-Panel auf:

Recipe JSON → styling.tokenGroups → Inspector Panel → Live Token-Editor

Jede Token-Gruppe wird als eigene Sektion im Inspector gerendert. Der Nutzer kann Token-Werte live ändern und sieht die Auswirkung sofort in den gerenderten Specimens.

Verbindung zu _component-tokens.scss

Die Token-Namen in tokenGroups müssen mit den in scss/scss/00-settings/_component-tokens.scss deklarierten :root-Variablen übereinstimmen: 

/* _component-tokens.scss */
:root {
  --nc-button-bg: var(--fnd-color-interactive-default);
  --nc-button-color: var(--fnd-color-on-accent);
  --nc-button-border: transparent;
  --nc-button-radius: var(--fnd-radius-sm);
  --nc-button-font-weight: var(--fnd-font-weight-semibold);
}
Validierung: lint-recipes.mjs prüft, ob alle in tokenGroups referenzierten Token-Namen auch in data/design-tokens.json unter dem jeweiligen Component-Eintrag existieren. Fehlende Tokens erzeugen einen Fehler.

Recipe SDK

Das Recipe SDK unter packages/recipe-sdk/index.js ist der programmatische Consumer von Recipe-Dateien. Es wird vom Theme Configurator und von Build-Skripten verwendet.

FunktionZweck
loadRecipe(json) Recipe parsen und normalisieren. Gibt ein validiertes Recipe-Objekt zurück.
buildSpecimenMatrix(recipe, specimenId) Generiert das Achsen × States Grid für ein bestimmtes Specimen.
resolveClasses(recipe, axisValues) Berechnet die vollständige CSS-Klassen-Liste für eine Achsen-Kombination.
extractTokens(recipe, group) Extrahiert alle Token-Namen für eine benannte Token-Gruppe.
validateSpecimenSanity(recipe) Prüft Specimens gegen definierte Achsen: fehlende Achsen-Referenzen oder ungültige Werte.

Pipeline

Der Weg vom Recipe-Authoring bis zur visuellen Darstellung im Theme Configurator:

01 Authoring Recipe JSON erstellen/bearbeiten
02 Validierung lint-recipes.mjs prüft Schema + Semantik
03 SDK Load loadRecipe() normalisiert + cacht
04 Rendering Theme Configurator rendert Specimens

Neues Recipe erstellen

Schritt-für-Schritt-Anleitung zum Erstellen eines neuen Recipes:

SchrittAktionDetails
1 Datei anlegen data/{component}-recipe.json mit meta-Sektion erstellen. Status: draft.
2 Achsen definieren Variationen identifizieren (variant, size, intent) und als axes modellieren.
3 Zustände festlegen states.supported und states.precedence definieren.
4 Token-Wiring styling.baseClasses, baseTokenGroups und tokenGroups verknüpfen.
5 Specimens erstellen Mindestens ein Specimen mit layout: "grid" für die Varianten-Matrix.
6 Validieren node scripts/lint-recipes.mjs ausführen — alle Fehler beheben.
7 Status hochstufen Nach Review: draft → experimental → stable.

Validierung

Der Recipe-Linter führt sowohl Schema-Validierung als auch semantische Prüfungen durch: 

# Alle Recipes validieren
node scripts/lint-recipes.mjs

# Exitcode 1 bei Fehlern, Warnungen sind nicht-blockierend
# Wird automatisch durch `npm test` ausgeführt
PrüfungSeverityBeschreibung
Schema-Validierung Error JSON-Struktur muss dem Schema recipe-schema.json entsprechen
Token-Existenz Error Alle Token-Namen in tokenGroups müssen in design-tokens.json existieren
Specimen-Achsen Error Specimens dürfen nur auf definierte Achsen verweisen
Modifier-Eindeutigkeit Error Innerhalb einer Achse muss jeder Modifier eindeutig sein
Fehlende Sektionen Warning Stable-Recipes sollten alle 9 Sektionen enthalten
Verwaiste Token-Gruppen Warning Token-Gruppen, die von keinem Achsen-Wert referenziert werden
