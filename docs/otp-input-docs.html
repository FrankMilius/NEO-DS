NEO Design System

OTP Input

PIN- und Code-Eingabefeld mit einzelnen Zellen für Einmal-Passwort (OTP), Verifizierungs-Codes und 2FA-Eingaben. Jede Zelle akzeptiert genau ein Zeichen. Kanonische Klasse: .nc-otp-input (BEM). Alle Werte kommen aus --nc-otp-* Component-Tokens.

Standard OTP (6-stellig)

Standard-OTP-Eingabe mit 6 einzelnen Zellen. Der Container hat role="group" und aria-label. Jede Zelle ist ein <input> mit maxlength="1" und inputmode="numeric". 

<div class="nc-otp-input" role="group" aria-label="Verifizierungs-Code">
  <input class="nc-otp-input__cell" type="text"
         maxlength="1" inputmode="numeric"
         autocomplete="one-time-code"
         aria-label="Stelle 1 von 6" pattern="[0-9]*" />
  <!-- weitere Zellen -->
</div>

Mit Separator

Optionales Trennzeichen (.nc-otp-input__separator) zwischen Zellen-Gruppen. Typisch bei 6-stelligen Codes: 3+3 mit Bindestrich. Der Separator ist user-select: none und nicht fokussierbar.

— 
<div class="nc-otp-input" role="group" aria-label="Verifizierungs-Code">
  <input class="nc-otp-input__cell" ... aria-label="Stelle 1 von 6" />
  <input class="nc-otp-input__cell" ... aria-label="Stelle 2 von 6" />
  <input class="nc-otp-input__cell" ... aria-label="Stelle 3 von 6" />
  <span class="nc-otp-input__separator" aria-hidden="true">&mdash;</span>
  <input class="nc-otp-input__cell" ... aria-label="Stelle 4 von 6" />
  <input class="nc-otp-input__cell" ... aria-label="Stelle 5 von 6" />
  <input class="nc-otp-input__cell" ... aria-label="Stelle 6 von 6" />
</div>

Zustände

Error-, Success- und Disabled-State werden als Modifier auf dem Container gesetzt. Alle Zellen innerhalb des Containers erhalten den State-Style.

Error — .nc-otp-input--error

Ungültiger Code. Bitte erneut versuchen.

Success — .nc-otp-input--success

Disabled — .nc-otp-input--disabled

<!-- Error -->
<div class="nc-otp-input nc-otp-input--error"
     role="group" aria-describedby="error-msg">...</div>
<p id="error-msg">Ungültiger Code.</p>

<!-- Success -->
<div class="nc-otp-input nc-otp-input--success" role="group">...</div>

<!-- Disabled -->
<div class="nc-otp-input nc-otp-input--disabled" role="group" aria-disabled="true">
  <input class="nc-otp-input__cell" disabled ... />
</div>

Filled State — .nc-otp-input__cell--filled

Visuelles Feedback für gefüllte Zellen: Hervorgehobener Rahmen in Focus-Farbe. Wird via JavaScript auf einzelne Zellen gesetzt, wenn diese einen Wert enthalten. 

<!-- JS setzt --filled wenn Zelle einen Wert hat -->
input.addEventListener('input', () => {
  input.classList.toggle('nc-otp-input__cell--filled', input.value.length > 0);
});

Accessibility Referenz

OTP-Eingaben stellen besondere Anforderungen: Korrekte Gruppierung, Auto-Focus-Verhalten und Ankündigung von Zuständen sind essenziell.

Gruppierung (WCAG 1.3.1, 4.1.2)

  • Container muss role="group" und aria-label="[Code-Bezeichnung]" haben
  • Jede Zelle braucht ein eindeutiges aria-label: “Stelle 1 von 6”, “Stelle 2 von 6” etc.
  • Alternativ: Ein sichtbares <label> für die Gruppe mit zugehörigem aria-labelledby
  • Separator-Elemente: aria-hidden="true" setzen — kein semantischer Inhalt für SR

Autocomplete & Keyboard (WCAG 1.3.5)

  • Erste Zelle: autocomplete="one-time-code" erlaubt Browser/OS automatisches Ausfüllen des OTPs
  • inputmode="numeric" zeigt auf mobilen Geräten die Zahlen-Tastatur
  • pattern="[0-9]*" zusätzliche Einschränkung auf Ziffern (auch für iOS-Tastatur)
  • Für alphanumerische Codes: inputmode="text", kein Pattern

Fokus-Management via JavaScript (WCAG 2.4.3)

  • Nach Eingabe in eine Zelle: Fokus automatisch auf nächste leere Zelle verschieben
  • Bei Rücktaste/Delete auf leerer Zelle: Fokus auf vorherige Zelle
  • Einfach-Fokus-Pattern: Kein Tab-Sprung zwischen Zellen; stattdessen Arrow-Keys oder Auto-Advance
  • Bei Paste des gesamten Codes: Code auf Zellen verteilen, letzter Zelle Fokus geben
  • Focus-Ring (:focus-visible) muss immer sichtbar sein

Fehler- und Success-States (WCAG 3.3.1)

  • Rahmenfarbe allein reicht nicht — immer eine textuelle Fehlermeldung bereitstellen
  • Fehlermeldung mit role="alert" oder aria-live="assertive" für sofortige Ankündigung
  • aria-describedby auf dem Container auf die Fehler-ID zeigen lassen
  • Success: Kurze positive Ankündigung via aria-live="polite"
  • Disabled-State: disabled-Attribut auf allen Zellen setzen; zusätzlich aria-disabled="true" auf dem Container

High Contrast Mode (WCAG 1.4.3)

  • OTP-Zellen unterstützen @media (forced-colors: active)
  • Im High Contrast Mode: Rahmen wird auf ButtonText gesetzt
  • Fokus: outline: 2px solid Highlight zusätzlich zum Rahmen
  • Keine eigenen Farb-Overrides im High Contrast Mode nötig — System-Farben übernehmen
