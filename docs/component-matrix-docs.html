Komponenten-Matrix

Semantik-Regeln

Die folgenden 7 Regeln definieren verbindliche Semantik-Entscheidungen für alle button-artigen Komponenten im Design System.

R1 Navigation ist immer Anchor

Jede Komponente, die den Benutzer zu einer neuen URL navigiert, muss ein <a href>-Element verwenden. Dies gilt auch dann, wenn die Komponente visuell wie ein Button aussieht. Links ermöglichen Rechtsklick → „In neuem Tab öffnen“ und sind für Screenreader als Navigation erkennbar.

Do
<a href="/dashboard" class="nc-tag nc-tag--clickable">
  Dashboard
</a>
Don't
<button onclick="navigate('/dashboard')"
  class="nc-tag">
  Dashboard
</button>
R2 Aktionen sind Buttons

Jede Komponente, die eine unmittelbare Aktion auslöst (Formular absenden, Dialog öffnen, Datei hochladen), muss ein <button>-Element verwenden. Niemals <a href="#"> oder <div onclick> für Aktionen verwenden.

Do
<button type="button" class="nc-chip"
  onclick="removeFilter()">
  Filter entfernen
</button>
Don't
<a href="#" class="nc-chip"
  onclick="removeFilter(); return false;">
  Filter entfernen
</a>
R3 Toggle ist aria-pressed (nicht aria-selected)

Wenn ein einzelner Button zwischen zwei Zuständen umschaltet (On/Off), muss aria-pressed verwendet werden. aria-selected ist für Tab-Panels und Listboxen reserviert, nicht für Toggle-Buttons.

Do
<button class="nc-toggle"
  aria-pressed="false">
  Favorit
</button>
Don't
<button class="nc-toggle"
  aria-selected="false">
  Favorit
</button>
R4 Single-Select: Radio schlägt Toggle

Wenn genau eine Option aus einer Gruppe gewählt werden kann (Single-Select), verwende das Radio-Pattern mit role="radiogroup" und role="radio". Dies ermöglicht korrekte Pfeil-Tasten-Navigation und Screenreader-Ansage „1 von 3 ausgewählt“.

Do
<div role="radiogroup" aria-label="Ansicht">
  <button role="radio"
    aria-checked="true">Liste</button>
  <button role="radio"
    aria-checked="false">Kacheln</button>
</div>
Don't
<div>
  <button aria-pressed="true">
    Liste</button>
  <button aria-pressed="false">
    Kacheln</button>
</div>
R5 Nicht interaktiv = nicht fokussierbar

Rein informative Elemente (Badges, statische Tags) dürfen keinen Fokus erhalten. Verwende <span> ohne tabindex. Kein role="button", kein onclick.

Do
<span class="nc-badge">Neu</span>
Don't
<span class="nc-badge" tabindex="0"
  role="button">Neu</span>
R6 Icon-only braucht immer Accessible Name

Jeder interaktive Button ohne sichtbaren Text muss einen barrierefreien Namen erhalten. Verwende aria-label auf dem Button oder aria-labelledby mit einem versteckten Text-Element. Gilt für Icon-Only Buttons, Close-Buttons und Icon-Chips.

Do
<button class="nc-chip nc-chip--icon-only"
  aria-label="Filter entfernen">
  <svg>...</svg>
</button>
Don't
<button class="nc-chip nc-chip--icon-only">
  <svg>...</svg>
</button>
<!-- Kein Accessible Name! -->
R7 Farbe nie als einziges Signal

Zustände (aktiv, ausgewählt, deaktiviert) dürfen nicht ausschließlich durch Farbe kommuniziert werden. Verwende zusätzlich: Icon-Wechsel, Textänderung, Border/Background-Kontrast oder ARIA-Attribute. Dies erfüllt WCAG 1.4.1 (Use of Color).

Do
<button aria-pressed="true"
  class="nc-toggle nc-toggle--active">
  <svg>✓</svg> Aktiv
</button>
<!-- Farbe + Icon + Text + ARIA -->
Don't
<button class="nc-toggle"
  style="background: green;">
  Filter
</button>
<!-- Nur Farbe signalisiert Zustand -->

Shared Architecture

Alle button-artigen Surface-Komponenten teilen eine gemeinsame Architektur aus Mixins, privaten CSS Custom Properties und einer Token-Hierarchie.

Interactive Surface Mixins

Drei Basis-Mixins bilden das Fundament aller Surface-Komponenten. Sie werden in den jeweiligen Komponent-SCSS-Dateien eingebunden.

Mixin Verwendung Beschreibung
static-surface-base Badge, statische Tags Nicht-interaktive Oberfläche: Display, Padding, Border-Radius, Typografie. Kein Focus-Ring, keine Hover/Active-States.
interactive-surface-base Chip, Toggle Group, Segmented Control, interaktive Tags Interaktive Oberfläche: Erweitert static-surface-base um Focus-Ring, Hover, Active, Disabled, Cursor und Transitions.
surface-size($size) Alle Surface-Komponenten Größen-Variante: Setzt Höhe, Padding, Font-Size, Icon-Size und Gap pro Größenstufe (sm/md/lg).

Verwendungsbeispiel

// Chip-Komponente .nc-chip { @include interactive-surface-base; @include surface-size('md'); // Default &--sm { @include surface-size('sm'); } &--lg { @include surface-size('lg'); } }

Token-Hierarchie

Tokens fließen in drei Ebenen: Foundation-Tokens definieren globale Werte, Component-Tokens spezialisieren diese für einzelne Komponenten, und Surface-Properties konsumieren sie im Mixin.

Foundation
--fnd-spacing-*  |  --fnd-radius-*  |  --fnd-color-*  |  --fnd-typography-*
Component
--nc-chip-*  |  --nc-tag-*  |  --nc-toggle-*  |  --nc-segmented-*
Surface
--_surface-height  |  --_surface-bg  |  --_surface-color  |  ...
// Beispiel: Wie ein Chip-Token durch die Hierarchie fließt // 1. Foundation (global) --fnd-spacing-03: 12px; --fnd-radius-full: 9999px; --fnd-color-background-tertiary: #f0f0f0; // 2. Component (chip-spezifisch) --nc-chip-padding-x-md: var(--fnd-spacing-03); // 12px --nc-chip-radius: var(--fnd-radius-full); // 9999px (Pill) --nc-chip-bg: var(--fnd-color-background-tertiary); // 3. Surface (privater Vertrag im Mixin) .nc-chip { --_surface-padding-x: var(--nc-chip-padding-x-md); --_surface-radius: var(--nc-chip-radius); --_surface-bg: var(--nc-chip-bg); }
